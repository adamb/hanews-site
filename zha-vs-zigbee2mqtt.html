ZHA vs Zigbee2MQTT: which Zigbee stack for Home Assistant?

HA News · 9 Nov 2026

There are two ways to run Zigbee devices in Home Assistant, and the choice confuses almost everyone on their first network. ZHA (Zigbee Home Automation) is a Zigbee gateway built into Home Assistant — you add a coordinator, and that's it. Zigbee2MQTT is a separate program that runs its own Zigbee network and passes devices to Home Assistant over MQTT. Both are fully local, and per Home Assistant's documentation ZHA is used by 25.4% of active installations, so the choice is live for a lot of houses. This comparison sticks to what the official ZHA and Zigbee2MQTT documentation says, and picks the simpler option for most homes.

The short answer

Start with ZHA if you are new to Zigbee and use Home Assistant as your home automation platform: it has no extra software to install and no MQTT broker to run. Switch to or start with Zigbee2MQTT if you want more granular control of device behaviour, a large device-specific configuration library, or if you already run other software against the same MQTT broker. Neither is "better" in the abstract — one is an integration, the other is a standalone stack.

What ZHA actually is

ZHA is hardware-independent Zigbee support compiled into Home Assistant itself, introduced in HA release 0.44 and classed by Home Assistant as "Local Polling" — everything runs on your machine. The integration supports exactly one dedicated coordinator on one Zigbee network, and the docs are explicit that the coordinator cannot be used by another application at the same time. You attach a USB adapter, click Add integration, pick Zigbee Home Automation, and start pairing. There is no broker, no extra container, no separate dashboard.

For a new network, the ZHA documentation recommends the Home Assistant Connect ZBT-2 USB adapter. The older Connect ZBT-1 is discontinued but fully supported, the Home Assistant Yellow's built-in radio is out of stock but supported, and the Home Assistant Green has no Zigbee radio at all and needs a USB adapter. Check Home Assistant Connect ZBT-2 on Amazon for current price and stock.

ZHA's device-type coverage is broad: alarm control panel, binary sensor, button, climate (marked beta), cover, device tracker, event, fan, infrared, light, lock, number, select, sensor, siren, switch, update and valve entities are all supported. But there is no official compatibility list; Home Assistant says ZHA supports all standard CSA Zigbee device types and points to blakadder's unofficial repository for specific models.

What Zigbee2MQTT actually is

Zigbee2MQTT needs three things per its getting-started guide: a Zigbee adapter (USB, GPIO, or a remote adapter over wired Ethernet), a host system to run on, and an MQTT broker. Mosquitto is the recommended broker. The software pairs devices to its own Zigbee network and publishes their state and commands to MQTT topics; Home Assistant picks them up through MQTT discovery.

That discovery integration is disabled by default — you must set homeassistant.enabled: true in Zigbee2MQTT's configuration. Discovery topics default to the homeassistant prefix, and the newer entity conventions (legacy_action_sensor, experimental_event_entities) are off unless you turn them on. It's one config file, but it is a config file, which is the practical difference from ZHA.

Zigbee2MQTT recommends adapters based on Texas Instruments' zStack or Silicon Labs' EmberZNet firmware, and requires coordinator firmware on the adapter — some ship preflashed. On chip choices, the documentation notes that a "P" suffix chip has a power amplifier (up to 20 dBm transmit versus 5 dBm on the non-P versions), and that CC2652 versus CC1352 makes no difference for Zigbee, which operates only in the 2.4 GHz band. Browse coordinators such as the SONOFF ZBDongle-E on Amazon or the SMLIGHT SLZB-07 on Amazon.

Two of those rows deserve emphasis, because they bite people.

Remote coordinators. ZHA's documentation advises against running the coordinator through any serial-over-IP, Wi-Fi, WAN or VPN bridge, because the serial protocol tolerates neither packet loss nor latency. Zigbee2MQTT says the same thing in its own way: Wi-Fi-attached adapters can be less stable, and if a local USB adapter is impossible, use a wired Ethernet remote adapter. If the radio must live in another room, choose Ethernet, not Wi-Fi, with either stack.

Firmware and backups. Zigbee 3.0 support in ZHA depends on coordinator firmware that the hardware vendor has to publish; older firmware may be manually upgradable. In Zigbee2MQTT, only zStack- and EmberZNet-based adapters support coordinator backups. Whichever stack you pick, buy an adapter on one of those two firmware families and you sidestep most of the friction.

Compatibility gotchas on both sides

The rule that surprises everyone: a Zigbee device can only belong to one network at a time. Devices previously paired to another Zigbee implementation — Hue, SmartThings, another Home Assistant box — must be factory-reset before they will join ZHA or Zigbee2MQTT. Per the ZHA documentation this is a Zigbee protocol limit set by the CSA, a Zigbee standards body, not a quirk of either piece of software. It also means migrating from one stack to another means re-pairing your devices; plan a weekend for it.

One ZHA-specific gap: the ZHA user interface cannot scan a QR code or Install Code for Zigbee 3.0 secure commissioning. The documented workaround is the zha.permit action called with the qr_code parameter, which is done from the Developer Tools section, not a button in the pairing dialog. Zigbee2MQTT handles install codes through its own settings. If your devices rely on install codes — some locks do — check which path you prefer before buying.

The coordinator question: can one stick serve both?

Both stacks work over the same hardware ecosystem. The ZHA documentation lists the Home Assistant Connect ZBT-2, the SONOFF ZBDongle-E (EFR32MG21), the SMLIGHT SLZB-07, TI CC2652/CC1352 USB adapters on Z-Stack coordinator firmware, and the dresden elektronik ConBee III as adapters tested with ZHA. Zigbee2MQTT recommends zStack and EmberZNet adapters, which covers the same popular sticks. So the coordinator you buy for ZHA today can serve a Zigbee2MQTT migration later — the network itself migrates, the devices don't (see the factory-reset rule above).

You can't have both stacks using one coordinator simultaneously, though: ZHA's docs state the dedicated coordinator can't be connected to or used by any other application while ZHA runs it. Running both stacks in parallel means two coordinators and two networks.

Which should you pick?

  • Pick ZHA if you use Home Assistant as your main platform, want the least configuration, already have a Connect ZBT-2 or another EmberZNet/zStack adapter, and your devices are mainstream brands. Zero extra moving parts.
  • Pick Zigbee2MQTT if you have a mixed-device network that needs per-device tuning, you already run an MQTT broker for other things, or you want its per-device documentation when something misbehaves. Also more natural if you run other home automation software alongside Home Assistant.
  • Pick neither-and-both if you like pain. Two coordinators on two USB ports genuinely work and some people keep a test network on Zigbee2MQTT while the house runs ZHA. Fine, but not a requirement.

Whichever you pick, both are local: ZHA runs as an in-process Home Assistant integration, Zigbee2MQTT as a separate service talking MQTT on your own network. Neither requires a vendor cloud account, which is the point of running Zigbee in the first place.

Setting up ZHA, briefly

  1. Plug the coordinator into the Home Assistant machine, ideally on a short USB extension cable to keep it away from USB 3 interference.
  2. Home Assistant should discover the adapter; otherwise Settings → Devices & services → Add integration → Zigbee Home Automation.
  3. Confirm the network forms. Note that ZHA wants this coordinator exclusively — don't point other software at the same serial device.
  4. Factory-reset anything that was paired to a vendor hub before, then pair mains-powered routers first, then battery sensors.
  5. For a device with an install code, use the zha.permit action with the qr_code parameter as documented.

Setting up Zigbee2MQTT, briefly

  1. Install Mosquitto (the recommended broker) and an MQTT integration in Home Assistant.
  2. Install Zigbee2MQTT — most people use the add-on on Home Assistant OS, others run the container on a host.
  3. Point it at your adapter in the configuration file; use a USB device or a wired Ethernet remote adapter, not Wi-Fi.
  4. Set homeassistant.enabled: true so devices appear in Home Assistant via MQTT discovery (it's off by default).
  5. Pair devices; reset anything joined to another network first.

FAQ

Is ZHA the same thing as Zigbee2MQTT?

No. ZHA is a Zigbee integration built into Home Assistant itself. Zigbee2MQTT is a separate application that runs its own Zigbee network and hands the devices to Home Assistant over MQTT.

Do I need an MQTT broker to run ZHA?

No. ZHA talks to the coordinator directly inside Home Assistant. An MQTT broker is required for Zigbee2MQTT, with Mosquitto as the recommended broker.

Can I move devices from ZHA to Zigbee2MQTT without re-pairing them?

No, not in general. Per the Zigbee standard set by the CSA, a device that has joined one Zigbee network must be factory-reset before it can join another, regardless of which software runs the coordinator.

Which Zigbee coordinator works with both ZHA and Zigbee2MQTT?

Adapters based on Silicon Labs EmberZNet or Texas Instruments zStack firmware, such as the Home Assistant Connect ZBT-2, the SONOFF ZBDongle-E and the SMLIGHT SLZB-07, are documented as working with both stacks.

Is Zigbee2MQTT harder to set up than ZHA?

It has one more moving part: Zigbee2MQTT needs an adapter, a host system and an MQTT broker, while ZHA runs inside Home Assistant with only the adapter. Zigbee2MQTT is usually installed as an add-on, which keeps the process manageable.

Does ZHA work with any Zigbee device?

ZHA supports all standard CSA Zigbee device types, but there is no official device compatibility list, and ZHA points to blakadder's unofficial repository for specific models. Some off-brand devices use non-standard clusters and work better in Zigbee2MQTT.
