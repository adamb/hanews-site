The Briefing

4 November 2026

The November release is out and it is unusually large: Core 2026.11.0 landed on 4 Nov with HACS rebuilt as a built-in Marketplace, a reworked entity-naming model that breaks some dashboard names, two-way audio for Matter cameras, LoRaWAN support and 38 new integrations. Also today: Z-Wave JS v15.32.1, and betas of HAOS 18.5 and ESPHome 2026.11.

01 · Home Assistant

Core 2026.11.0 ships — HACS becomes the built-in Marketplace

What happened: Home Assistant released Core 2026.11.0 on 4 Nov. The headline change is the Marketplace: the Home Assistant Community Store, HACS, is now part of Home Assistant itself, reachable from Settings on every installation type. The project says existing HACS installs stay installed and keep updating. stable.json now lists Core 2026.11.0.

Why it matters: HACS was the first thing many people installed after flashing, and its install step was a hurdle for everyone else. Folding it into the core makes custom cards, themes and integrations a supported in-product path rather than a bootstrap ritual. If you run HACS today, check that your custom repositories and installed items survived the transition before you rebuild a dashboard on top of them. The release notes also count 38 new integrations.

Core 2026.11.0; 2026.11: A lot in store!; stable.json

02 · Automations

Exclude items from a target — the exception that stays an exception

What happened: Service calls and targets can now exclude specific entities. Turning on all the lights downstairs except the kitchen one becomes a single action rather than a template or a second script. The release notes say the exclusion is evaluated at run time, so a light added to the kitchen next month is excluded too.

Why it matters: The old workaround was an inline template that filtered the entity list by hand — correct, but fragile and invisible to anyone reading the automation later. A first-class exclude makes the exception readable, and it survives new devices in the same area, which is exactly the part hand-written filters got wrong.

2026.11 release notes — Exclude items from a target

03 · Home Assistant

Entity naming reworked — a backward-incompatible change you will notice

What happened: 2026.11 reworks how entity names are assembled: you name a thing once and Home Assistant adds the surrounding context itself. The project flags this as a backward-incompatible change and warns that some names on existing dashboards will look different after updating. It has a separate post explaining the model.

Why it matters: This is the change most likely to touch a working house. Names show up in dashboards, automations, voice assistants and notification templates; anything that matched an old friendly name literally can stop matching. Read the naming post before you press update, and take a backup so you can compare.

Primary source
Naming things in Home Assistant, shaped by your feedback; 2026.11 release notes

04 · Matter & Thread

Matter cameras can now talk back

What happened: 2026.11 adds two-way audio for Matter cameras in Home Assistant — the release notes describe cameras you can talk back through. Matter camera support already existed; this release adds the outbound audio path.

Why it matters: Talk-back is the difference between a camera you watch and a camera you can use at the front door. It also puts pressure on the camera vendors: a Matter camera that implements the speaker path works locally in Home Assistant without the vendor app in the loop. Check the vendor's Matter implementation before assuming the microphone on your existing model works.

Primary source
2026.11 release notes — Talk back through your cameras

05 · Radios

LoRaWAN support, and batteryless switches on Zigbee Green Power

What happened: The November release adds LoRaWAN support — the long-range, low-power radio family — and support for batteryless switches that run on Zigbee Green Power, which harvests the energy of the button press itself. Both appear as sections of the 2026.11 release notes.

Why it matters: These are the two radio paths that reach places Wi-Fi and normal Zigbee batteries cannot: a sensor in a field or a barn, and a switch on a wall with no wiring and no battery to change. Neither is a mainstream install yet — LoRaWAN needs a gateway and a network server — but it is the first time both sit inside core Home Assistant rather than in a custom integration.

Primary source
2026.11 release notes — LoRaWAN; — Zigbee Green Power

06 · Local control

Backups and media can live on local drives

What happened: Home Assistant 2026.11 can store backups and media on local drives instead of only in the cloud or the internal disk, per the release notes.

Why it matters: Backups have been the most common reason people keep a Nabu Casa subscription even when everything else in their house runs locally. A local target does not replace an off-site copy — a house fire takes both — but it makes a local-first setup honest about where the data sits. Pair it with a sync you control.

Primary source
2026.11 release notes — Store backups and media on local drives

07 · Home Assistant OS (beta)

HAOS 18.5.rc1 — release candidate for the operating system

What happened: Home Assistant OS tagged 18.5.rc1 on 3 Nov. The stable channel stays at 18.4, released 27 Oct.

Why it matters: The OS release is the one update you cannot roll back from the UI if the box will not boot, and it carries the kernel and container runtime under everything else. Leave an rc of the operating system alone on a house that has to work tomorrow.

Primary source
HAOS 18.5.rc1; stable.json

08 · ESPHome

ESPHome 2026.11.0b1 opens the November beta; stable stays 2026.10.2

What happened: ESPHome tagged 2026.11.0b1 on 4 Nov, the first beta of its November cycle. The stable channel is on 2026.10.2, released 2 Nov. The project has not yet published its monthly release post for 2026.11.

Why it matters: ESPHome betas are for the board on your bench. A failed flash is recoverable over serial, but only if you can physically reach the device — so beta builds belong on hardware you can unplug, never on the node behind a wall switch.

Primary source
ESPHome 2026.11.0b1; ESPHome blog

09 · Z-Wave

Z-Wave JS v15.32.1 — driver update behind Z-Wave JS UI

What happened: Z-Wave JS moved from v15.31.2 to v15.32.1 on 4 Nov. Z-Wave JS UI stays at v11.25.2, from 26 Oct.

Why it matters: The driver is what actually talks to your stick and your devices; UI releases usually lag it. If you run Z-Wave JS UI, check its changelog for the bundled driver version before you update — a driver bump is the release most likely to change how an older device behaves.

Primary source
zwave-js v15.32.1; Z-Wave JS UI v11.25.2

10 · Community

Community Day is Saturday 7 November; the WTH month is still open

What happened: The release post repeats two dates: the Month of “What the Heck?!” runs through November, with the project asking non-technical household members to file what annoys them; and Community Day is Saturday 7 Nov, with 97 meetups in more than 30 countries.

Why it matters: WTH is the one feedback channel where a complaint about setup friction actually changes the product, and it is aimed this year at the people who did not install Home Assistant. If you administer a house for someone else, file what they hit.

Primary source
“What the Heck?!” 2026; 2026.11 release notes

11 · The stack

Version table: where every moving part sits this evening

What happened: Four things moved since the 3 Nov check: Core from 2026.10.4 to 2026.11.0 on stable, HAOS to an 18.5 release candidate, ESPHome to a 2026.11 beta, and Z-Wave JS from v15.31.2 to v15.32.1. Supervisor, Z-Wave JS UI, Zigbee2MQTT and matter.js are unchanged.

Why it matters: One of the four is a stable release for everyone (Core), one is a driver bump behind a UI (Z-Wave JS), and two are betas you should ignore unless the hardware is on your bench.
