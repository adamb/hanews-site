Zigbee vs Thread: which radio should your house use?

HA News · 5 Nov 2026

Zigbee and Thread get compared as if they were two brands of the same product. They are not, and the difference is structural. Zigbee is a mesh network your devices speak, with an application layer baked in and one coordinator running it. Thread is a mesh network and nothing else — the Thread Group calls it a networking layer and leaves the application layer to somebody else, usually Matter. Once you hold that distinction, the rest of the comparison falls into place: why a Thread device needs a border router, why your Zigbee stick will not control it, and why Matter keeps appearing in a conversation that was supposed to be about radios.

The short version

  • You already own Zigbee sensors, bulbs, buttons or locks. Keep them on a Zigbee coordinator, driven by Zigbee Home Automation (ZHA) or Zigbee2MQTT. Per the ZHA documentation, that covers alarm panels, binary sensors, buttons, climate (beta), covers, device trackers, events, fans, lights, locks, numbers, selects, sensors, sirens, switches, valves and update entities — all local.
  • You are buying hardware that says "Matter over Thread". You need two separate things: a Thread border router to carry the traffic, and a Matter controller to control the device. Home Assistant supplies the second in software. The first is a piece of hardware you may already own and not know about.
  • You want one answer. Zigbee is the mature, cheap, wide-catalogue path for sensors and bulbs today. Thread is the path with a future, because it is the network Matter was designed to run over. Nothing forces you to choose: a coordinator and a border router coexist in the same house without arguing.

Thread is a network, not a language

Thread runs on the IEEE 802.15.4 MAC/PHY layer — the same low-power radio family Zigbee sits on — and builds an open, IPv6-based protocol on top of it, for device-to-device and device-to-cloud connections. It provides security at the network layer. The Thread Group positions it for a low energy footprint in homes and buildings, which is exactly the property that makes it interesting for a door sensor that has to last years on a coin cell.

Then comes the sentence that explains a hundred support threads. The Thread Group describes Thread as a networking layer, not an application layer: vendors "select an application layer" separately, through another IoT organisation or with their own. Thread carries bytes. It does not decide what "on", "22 degrees" or "locked" mean. That is why a Thread device without a controller is a brick with a radio, and why the Home Assistant docs say Matter and Apple HomeKit are the protocols "responsible for handling the Thread credentials and connecting your Thread device to the Thread network."

On the open-source side, OpenThread is Google-originated and ships an OpenThread Border Router and an OpenThread Commissioner for building Thread networks. That is the stack Home Assistant leans on when it runs the OpenThread Border Router add-on.

What Zigbee looks like in a Home Assistant house

Zigbee is a low-power mesh of devices with low-bandwidth radios, coordinated by exactly one coordinator. The ZHA integration is a hardware-independent gateway that can replace most proprietary Zigbee bridges and hubs: you plug a coordinator radio adapter into the machine running Home Assistant — typically a USB stick — and every device pairs to that one network.

ZHA handles OTA firmware updates for Zigbee devices, groups and binding, a network topology view, and migration to a new adapter without re-pairing anything. If you have no coordinator yet, the docs recommend Home Assistant's own Connect ZBT-2, list tested and compatible adapters, and keep a third tier marked "supported but not recommended".

The alternative stack is Zigbee2MQTT, which talks to Home Assistant over MQTT. It has one hard requirement the docs are blunt about: the adapter has to be flashed with coordinator firmware before use, though some ship pre-flashed. Its recommended families are Texas Instruments zStack (CC2652 and CC1352), Silicon Labs EmberZNet and Dresden Elektronik deCONZ, with "not recommended" and "experimental" tiers below those. If you want the buying detail, our Zigbee hub guide walks the hardware side, and Zigbee vs Z-Wave covers the older comparison.

What a Thread network looks like

Thread needs a border router: a device that bridges the 802.15.4 mesh to your IP network, and in most homes that is a speaker or a hub you already bought for something else. Home Assistant's Thread integration tracks the different Thread networks in your home and stores their credentials — the docs compare them to a Wi-Fi password, which is the right mental model. Lose the credentials and you re-commission devices.

You never install that integration by hand. It appears automatically when Home Assistant detects a border router, and the docs still label it a work in progress. The Thread panel is where the maintenance lives: combining separate Thread networks, changing the Thread channel, migrating a network to a new adapter, and adding a third-party Thread adapter to the OpenThread Border Router app.

Where Matter fits — and what "Matter vs Zigbee" really asks

Matter is the application layer. The Home Assistant Matter integration controls Matter devices on a local Wi-Fi or Thread network. Home Assistant runs its own Matter controller as a separate app and process, the Matter Server; the integration talks to it over a WebSocket, and the controller maintains the Fabric (Matter's term for the set of controllers that share authority over a device).

Matter 1.0 was published in October 2022 under the Connectivity Standards Alliance, with Apple, Google and Amazon as backers, and the docs are honest that adoption is still in progress. Matter devices run locally and allow local control without an internet connection. The integration supports OTA device updates, a network map view, sharing a device from another controller, and Matter bridges inside Home Assistant.

So "Matter vs Zigbee" is a category error of a different kind: Matter is a language, Zigbee is a network that speaks its own. The useful comparison is Thread versus Zigbee at the transport, and Matter versus the Zigbee application layer above it. Compatibility: the five things people get wrong

  1. "Built on Thread: requires border router" is a hard requirement, not a suggestion. Per the Home Assistant docs, that label means Thread is the only supported network protocol for the device — Wi-Fi cannot reach it. No border router, no device.
  2. A border router is not a controller. It moves packets. It does not give you a switch to press. You still need Matter or HomeKit in the middle.
  3. Your Zigbee coordinator will not adopt a Thread device. They are different networks with different credentials and different radios in the Home Assistant model.
  4. Home Assistant hides the Thread integration until it sees a border router. If the Thread panel is missing from Settings, that is the reason, not a broken install.
  5. Zigbee2MQTT will not talk to an unflashed adapter. Coordinator firmware first; some adapters arrive pre-flashed, many do not.

Setting up Zigbee, in order

  1. Choose a coordinator. With no adapter in hand, the ZHA docs point at the Connect ZBT-2; Zigbee2MQTT users should stay inside the zStack, EmberZNet and deCONZ families.
  2. Plug it into the Home Assistant machine. ZHA treats it as a gateway: one Zigbee network that you add devices to.
  3. Open Settings, then Devices & services. ZHA usually shows up as discovered; if it does not, add the Zigbee Home Automation integration manually.
  4. Create the network, or migrate from the old adapter. The migration path is documented and avoids re-pairing devices.
  5. Pair mains-powered devices first so they can route, then the battery devices. Turn on OTA updates if you want the coordinator pushing firmware to devices that support it.

Setting up Thread and Matter, in order

  1. Get a border router onto the network, or confirm one you already have. Home Assistant will only surface the Thread integration once it detects one.
  2. Open the Thread panel and look at what it found. If you have more than one Thread network, this is where you combine them, and where you change the channel or migrate to a new adapter later.
  3. Make sure the Matter integration is running. It is a separate process from the core — the Matter Server — and the integration reaches it over a WebSocket.
  4. Add the device through Matter, not Thread. The Matter controller maintains the Fabric and handles the Thread credentials on the device's behalf.
  5. Check the network map if a device drops. The Matter integration exposes one, and the Thread panel shows which network a device landed on.

Should you replace Zigbee with Thread?

No, and the documentation does not ask you to. ZHA's device coverage is wide, entirely local, and includes the unglamorous classes — valves, sirens, device trackers — that a real house accumulates. Thread's advantage is not that it is a better radio; it is that Matter runs over it, and Matter is where new certified hardware is heading.

The sane plan for most homes is both: leave the Zigbee mesh alone, add a border router when you start buying Matter-over-Thread gear, and let Home Assistant hold the two together. Treat Thread as the network you grow into rather than the one you migrate to. If you are choosing a first hub rather than a first protocol, our Matter & Thread section has the device-side coverage.

FAQ

Is Thread the same thing as Matter?

No. Thread is the network the device talks over; Matter is the application layer that controls it. The Thread Group describes Thread as a networking layer and says vendors select an application layer separately. Home Assistant's Thread documentation names Matter and Apple HomeKit as the protocols that handle Thread credentials and connect a Thread device to the network.

Can Home Assistant talk to Thread devices without a Matter controller?

Not through the Thread integration alone. That integration tracks the Thread networks in your home and stores their credentials. Control comes from an application layer: Matter or HomeKit. Home Assistant ships a Matter integration and runs its own Matter controller as a separate process, the Matter Server.

Do I need a border router for Thread, and is a Zigbee coordinator the same thing?

Yes for the first, no for the second. Home Assistant only shows the Thread integration once it detects a border router. A Zigbee coordinator is a different job: the single radio that runs a Zigbee mesh, which ZHA or Zigbee2MQTT adds devices to.

Which is better for battery-powered sensors, Zigbee or Thread?

Both were designed for it. The ZHA documentation describes Zigbee as a low-power mesh of devices with low-bandwidth radios, and the Thread Group positions Thread for a low energy footprint in the home. In practice the deciding factor is which devices exist in the shape you need, not the radio underneath.

Can one radio dongle do both Zigbee and Thread?

Treat them as two pieces of hardware. Home Assistant's documentation keeps the Zigbee coordinator and the Thread border router separate, documents how to add a third-party Thread adapter to the OpenThread Border Router app, and documents migrating a Zigbee network to a new adapter without re-pairing.

Should I replace my Zigbee devices with Thread ones?

There is no need to hurry. ZHA covers a broad set of device classes locally and supports groups, binding, OTA firmware updates and adapter migration. Add Thread when you buy Matter-over-Thread hardware, and run both networks side by side.
