OpenWrt for the smart home: what it is and which routers to run it on (2026)

HA News · 6 Nov 2026

OpenWrt is a Linux-based firmware for routers, maintained by an open-source project instead of a hardware vendor. You flash it over the stock firmware and get a router you can log into, script and extend: a VPN server, DNS filtering for the kids' tablets, a separate network for the smart-home gear, traffic counters you can chart. The reason to care is control — the router is the one box every device in the house depends on, and OpenWrt is the only common way to own its software.

This page is the standing reference for the OpenWrt cluster on HA News: what the project shipped, what changed in the current release, which routers have official builds, and how to get the router talking to Home Assistant. Everything below is sourced from the OpenWrt release notes and the project's own downloads index, both linked in full at the foot of the page.

What OpenWrt actually is

A router you buy in a shop runs firmware written by the manufacturer, usually locked down, usually supported for a couple of years, usually with a cloud app attached. OpenWrt is the other arrangement. It is a Linux distribution built for embedded network hardware, cut per release and per device target, with a package manager on top so software can be added and removed after the fact. Configuration lives in plain text under /etc/config and survives a reboot; shell history on 24.10 and 25.12 is stored in RAM and disappears when the box restarts, a deliberate change so that commands typed into a router don't end up in flash.

It also means you can keep a router working long after the vendor has moved on. A 2016 access point running current OpenWrt still gets security patches; the same box on stock firmware probably stopped getting them years ago. If you would rather compare it against the other common DIY router platform, our piece on OpenWrt vs DD-WRT covers where each one fits.

Where the project stands in November 2026

Current stable is OpenWrt 25.12.6, published 18 October 2026. The previous series, 24.10, is at 24.10.8, published 26 July 2026, and is now in security maintenance only. The 24.10 release notes put its end of life at September 2026 and recommend migrating to 25.12. In practice: a 24.10 box still works and still gets security fixes for now, but it is not where new work is happening, and every month you leave it there the upgrade gets slightly more annoying.

The project's own numbers give a sense of scale. The 24.10 release notes describe support for over 1,970 devices; the official build index we cached on 5 November 2026 holds 2,187 device profiles with firmware for 24.10.8 and/or 25.12.6. That is a lot of hardware, and almost none of it was sold as an OpenWrt device.

The 25.12 change that matters: opkg is gone

OpenWrt 25.12 switched its package manager from opkg to apk, the Alpine Package Keeper. This is the single most consequential change in the release, because it invalidates muscle memory. Every guide you have bookmarked that says opkg update is describing the old world. It also means the two series do not share packages: 24.10 is opkg-only and does not accept apk packages, so you cannot mix a 25.12 package feed into a 24.10 install and expect it to work.

Why it matters at home: if you follow an old tutorial on a fresh 25.12 install and the commands fail, that is not a broken router. It is a package manager change. Read the release notes for the version you actually flashed, not the top search result.

Upgrading without a brick: attended sysupgrade

The second change is quieter and much more useful for people who don't want a weekend project. OpenWrt 25.12 installs attended sysupgrade in LuCI by default, and adds the owut command-line tool on devices with enough flash. Attended sysupgrade does not flash a generic image over your configuration. It asks the build server to produce an image with your installed packages already included, then flashes that, preserving configuration.

The practical effect is that the riskiest part of an OpenWrt upgrade — reinstalling a dozen packages afterwards, one at a time, hoping two of them don't conflict — mostly goes away on devices that can host it. Small-flash routers still may not fit the tool or the rebuilt image. That is the number to check before you pick hardware: flash size, not Wi-Fi speed.

Back up before you start regardless. Attended sysupgrade preserves configuration; it does not preserve your patience if the power drops mid-flash. Put the router on a UPS if the grid is unreliable where you live.

Does my router have an official build?

OpenWrt support is per model, and sometimes per hardware revision, which is why the answer should come from the project rather than a shop listing. Two tools exist:

  • The Firmware Selector at firmware-selector.openwrt.org: pick the release, the target and the device profile, and download the correct image. It can also bake packages into the image.
  • The downloads index at downloads.openwrt.org: the raw directory tree behind the selector, useful for confirming a profile name exists in a given release.

Note that the openwrt.org wiki now sits behind an Anubis proof-of-work bot wall and returns nothing to a plain fetch, so device support on this page was verified from the downloads index instead. Humans in a browser will not notice the wall; scripts will.

Getting the router talking to Home Assistant

Two integrations cover most of what people want, and neither needs a cloud account.

Router statistics. Home Assistant's built-in UPnP/IGD integration collects network statistics straight from the router: bytes in and out, packets in and out, uptime, the WAN address and WAN connectivity status, exposed as sensors plus a binary sensor. It auto-discovers, and it needs UPnP or NAT-PMP enabled on the router — on OpenWrt that is the miniupnpd package. Enabling UPnP on a router is not free: it lets LAN devices ask for port mappings. If that trade bothers you, skip the integration and poll the router another way.

A coordinator over the network. If your Zigbee or Thread radio has to live somewhere other than the Home Assistant box — a shed, a garage, the middle of a long house — Zigbee2MQTT accepts a TCP endpoint in place of a local serial device, for example port: tcp://192.168.1.12:6638. It also supports mDNS discovery for tested network coordinators: SLZB-06, UZG-01 and CZC-01. An OpenWrt box with a 5 V USB port becomes the power and network drop for that radio. Read the adapter settings documentation before ordering hardware; it lists which coordinators have been tested on the network path.

Gotchas worth knowing before you flash

  • Flash size decides what you can install. Attended sysupgrade and owut need room; so does anything with a web UI on top. 128 MB of flash is a much better floor than 16 MB.
  • Per-revision support is real. The Archer AX23 example is v1 only. Router vendors change chips mid-life without renaming the box.
  • The wiki is bot-walled. Community documentation on openwrt.org is fine in a browser, but automated fetches return an Anubis challenge. Keep local copies of the pages for your hardware.
  • 24.10 packages won't load on 25.12, or the reverse. Plan the upgrade as a migration, not an update.
  • Don't put the router and the Zigbee radio on the same USB 3 controller. It is the classic interference story, and it is why extension cables exist.

FAQ

What is OpenWrt, in one paragraph?

OpenWrt is a Linux-based firmware for routers and other small network devices, maintained as an open-source project rather than by a hardware vendor. It replaces the stock firmware with a writable filesystem and a package manager, so you can add features — VPN servers, DNS filtering, network monitoring — without buying new hardware.

Is OpenWrt Linux?

Yes. OpenWrt is a Linux distribution built for embedded network hardware, and it is packaged like one: builds are cut per release and per device target. Since release 25.12 the package manager is apk, the Alpine Package Keeper, replacing opkg.

Which routers have official OpenWrt support?

The project's official downloads index lists 2,187 device profiles with builds for 24.10.8 and/or 25.12.6 as of early November 2026. Check a specific model in the OpenWrt Firmware Selector by target and profile name before you buy; support is per model and sometimes per hardware revision.

Does the OpenWrt Firmware Selector keep my installed packages?

The selector can build an image with packages baked in, which is how attended sysupgrade works. On 25.12 attended sysupgrade is installed in LuCI by default and rebuilds an image with your installed packages while preserving configuration. Devices with larger flash also get the owut command-line tool.

Should I run OpenWrt on my main router or on a separate box?

On the main router if you want one device doing routing, Wi-Fi and filtering. Run it on a separate box — a travel router or an x86 mini PC — if you would rather not risk the house network while learning, or if you want the router and the Zigbee or Thread coordinator in different places.

How do I get router statistics into Home Assistant?

Enable UPnP or NAT-PMP on the router — miniupnpd is the OpenWrt package for it — and add Home Assistant's built-in UPnP/IGD integration. It creates sensors for bytes and packets in and out, uptime and the WAN address, plus a binary sensor for WAN connectivity, and it is auto-discoverable.

Is 24.10 still supported, and how do I move to 25.12?

24.10 is in security maintenance only. The project put end of life at September 2026 and recommends migrating to 25.12. Move with attended sysupgrade where your device has the flash for it, keep a copy of your configuration, and expect to reinstall packages by hand if you script the upgrade: 24.10 is opkg-only and does not accept apk packages.
