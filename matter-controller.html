What is a Matter controller? Home Assistant, Apple, Google, Alexa and SmartThings explained

HA News · 10 Nov 2026

You will see the word "controller" all over Matter packaging and documentation, and it is easy to confuse with a hub or a border router. A Matter controller is the app or device in an ecosystem that actually controls Matter devices: it holds the device list, commissions new devices onto the network, and sends them commands. Apple Home, Google Home, Amazon Alexa, Samsung SmartThings and Home Assistant can all act as controllers. Home Assistant runs its own Matter controller as the Matter Server app, which runs as a separate process and connects the Matter network — the fabric — to Home Assistant over WebSocket.

The short answer to "should I buy a Matter controller?" is usually no: you probably already own one. A HomePod, a Nest device, an Echo or a SmartThings Station is already a controller. What you may need to add is a Thread border router or a radio for Home Assistant, which is a different job.

Controller, hub, border router: three different jobs

Matter stacks several roles on top of ordinary networking hardware, which is why the naming gets confusing.

The controller works at the application layer. It knows which devices exist on your Matter fabric, commissions them, and issues the commands that turn lights on or lock doors. Every ecosystem you join a device to runs one controller of its own.

A Thread border router is infrastructure, not software. Per the Home Assistant Thread documentation, a border router routes packets between the Thread mesh and other IP networks, and does not control devices. Device control is application-layer work — Matter or HomeKit — and a border router can serve a network without ever sending a single command. A Thread network supports several border routers at once for coverage and redundancy.

A hub is whatever the vendor says it is. Some hubs are controllers, some are border routers, some are both, and some are Matter bridges. The word on the box tells you nothing about the role; check the spec sheet.

It helps to remember what sits underneath. Matter is an application-layer service-control protocol running over IPv6 on your existing LAN — Wi-Fi or Ethernet — or over Thread. It has no radio of its own. Thread is a low-power mesh networking protocol on IEEE 802.15.4 RF, the same radio as Zigbee, that is IP-addressable. Thread alone does not control devices; a higher-layer protocol such as Matter or HomeKit is required. Details in our Matter primer and Thread border router guide.

Which devices are Matter controllers

Home Assistant's Matter integration documentation lists the controllers you are likely to already own:

  • Home Assistant, running the Matter Server app (formerly the Matter add-on). It runs as a separate process and connects the Matter fabric to Home Assistant over WebSocket.
  • Google Nest products, such as Nest Hub and Nest speakers.
  • Apple HomePod speakers, which control Matter devices for the Apple Home ecosystem.
  • Samsung SmartThings Station.
  • Some newer Amazon Echo devices for Alexa.

Home Assistant as a Matter controller

Setup is straightforward on HA OS. Add the Matter integration; on a regular Home Assistant OS install, submit to install the official Matter Server app. It is not supported on 32-bit platforms. Commissioning — the pairing step that adds a device to your fabric — needs Bluetooth: Android 8.1 or later (12+ recommended), iOS 16 or later, and the latest Home Assistant Companion app.

Once a device is commissioned, it talks to Home Assistant locally. Matter always allows local control and needs no internet connection for device control; the cloud never sits between your switch and your light. Some vendors, though, require an account on their own hub before they will enable Matter support on that hub — worth checking before you buy, if cloud accounts bother you.

A practical tip the documentation repeats: keep the QR code or numeric setup code from the packaging. You need it to re-commission a device after a reset, so photograph the code and store it somewhere you can find it again.

Multi-admin: one device, several controllers

Matter's most useful property is that a device can be joined to multiple controllers — the multi-admin, or multi-fabric, feature documented in the Home Assistant Matter integration. A lock commissioned to Apple Home can also be shared to Home Assistant, and it keeps working in both.

In Home Assistant the path is Settings, then Connectivity, then Matter, then Add device, then answer "Yes. It's already in use." and choose the existing controller — for example Google Home. The device stays paired to the original ecosystem; Home Assistant simply joins its fabric alongside.

A familiar trap: Thread does not mean Matter

The most common buying mistake is assuming a "Thread device" is a Matter device. It is not. Some Thread devices support only HomeKit or another vendor protocol, and some need beta firmware before they can speak Matter at all. The Home Assistant docs are blunt about it: look for the Matter logo, not the Thread logo.

Read the packaging the same way. "Built on Thread: requires border router" means Thread is the only network protocol on board — no Wi-Fi — so you need a border router somewhere in the house. The Matter or HomeKit logo on the same box names the control protocol.

Matter bridges: when your existing hub joins the fabric

You do not have to abandon old hardware. Matter bridges expose a hub's non-Matter devices as Matter devices, while the vendor's native app keeps working at the same time. Documented examples include the SwitchBot Hub 2, Aqara Hub M2, Ikea DIRIGERA and the Philips Hue Bridge. If you own a house full of Zigbee devices, a bridge is often the cheapest route into a Matter fabric without re-pairing anything.

Home Assistant itself is not a bridge: it cannot turn your existing Home Assistant devices into Matter devices for other ecosystems to control. And bridging is not a full translation — feature coverage varies. The SwitchBot Hub 2 at firmware V1.5 exposes curtains, locks and blinds via Matter but not lights, so check the bridge's coverage list before assuming everything will appear.

FAQ

What is a Matter controller and is Home Assistant one?

A Matter controller is the app or device in an ecosystem that controls Matter devices. Home Assistant is one: it runs the Matter Server app, its own Matter controller, which joins devices to the Matter fabric and connects it to Home Assistant over WebSocket.

What is the difference between a Matter controller, a hub and a Thread border router?

The controller holds the device list and controls devices at the application layer. A Thread border router routes packets between the Thread mesh and other IP networks and does not control devices. A hub can be either or both, depending on the vendor.

Does a Thread device automatically work with Matter?

No. Thread is only the network. Some Thread devices support HomeKit or another vendor protocol instead of Matter, and some need a firmware update. Look for the Matter logo, not the Thread logo.

Which controllers work: Apple Home, Google Home, Alexa, SmartThings, Home Assistant?

Per Home Assistant's Matter documentation, controllers include Google Nest products, Apple HomePod speakers, Samsung SmartThings Station, some newer Amazon Echo devices, and Home Assistant running the Matter Server app.

Can one Matter device be controlled by two ecosystems (multi-admin)?

Yes. Multi-admin lets a Matter device join multiple controllers on separate fabrics. In Home Assistant you add an already-commissioned device via Settings, Connectivity, Matter, Add device, then choose "Yes. It's already in use."

Can I share a device from Apple Home or Google Home to Home Assistant?

Yes, via multi-admin. In the Home Assistant Companion app, add the device as already in use and pick the existing controller, such as Google Home. The device stays paired to the original ecosystem too.
