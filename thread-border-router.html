What is a Thread border router (and do you already own one)?

HA News · 10 Nov 2026

A Thread border router is the device that connects a Thread mesh network to everything else: your Wi-Fi, your Ethernet switch, the internet. A Thread network can't reach any other network without one. If you plan to add Matter devices over Thread — sensors, locks, bulbs from brands like Eve, Nanoleaf or IKEA — and control them from your phone, a hub, or Home Assistant, you need a border router somewhere in the house. The good news: many people already own one and haven't noticed. A HomePod mini on a shelf or a Nest Hub in the kitchen is acting as one right now.

Thread itself is an IEEE 802.15.4 protocol, the same low-power radio standard that Zigbee builds on, but it is IPv6-based, carries network-layer security, and supports device-to-device and device-to-cloud connectivity. That per the Thread Group's description. In plain terms: Thread devices form a self-healing mesh that sips battery power, and the border router is the doorway between that mesh and the rest of your network. For how Thread stacks up against Zigbee in practice, read our Thread network guide.

What a border router actually does

The OpenThread documentation — OpenThread being the open-source Thread implementation that most consumer products build on — lists what a border router must support. Per the OpenThread border router guide, the essentials are:

  • Bidirectional IP connectivity between the Thread network and Wi-Fi or Ethernet — traffic flows both ways, so an app on your phone can reach a sensor and the sensor can be reached back.
  • Bidirectional DNS-based service discovery — mDNS on the infrastructure side, SRP on the Thread side — so devices can find each other by name without manual configuration.
  • Thread-over-infrastructure, which merges Thread network partitions across IP links. This is what lets two border routers in different rooms keep one logical Thread network.
  • External Thread commissioning — letting a new device join the network, driven from outside the mesh, typically from your phone.

Notice what is not on the list: a vendor account, a subscription, or a hub with a screen. A border router is infrastructure. That is the part people miss when they shop for "a Thread hub" — the role is defined by function, and devices that fill the function are already scattered through Apple, Google, and Amazon product lines.

Devices you already own that are Thread border routers

Home Assistant keeps a list of devices that act as Thread border routers in its Thread integration documentation. By that list:

  • Apple: HomePod (2nd generation), HomePod mini, Apple TV 4K (3rd generation, Wi-Fi + Ethernet), Apple TV 4K (2nd generation, Wi-Fi). Apple recommends the Wi-Fi + Ethernet Apple TV models as the preferred always-on border router.
  • Google: Nest Hub (2nd gen), Nest Hub Max, Nest Wifi Pro (Wi-Fi 6E), Nest Wifi, and the Google TV Streamer (4K).
  • Others: Nanoleaf and Amazon also sell border-router-capable devices.

The practical takeaway is that most houses with a smart speaker are already running a Thread network without knowing it. If you are setting up Matter, that is good news — the hard infrastructure requirement is commonly already met. If you want to shop for a dedicated border router instead, these are the devices most commonly bought for the role:

  • HomePod mini on Amazon — the cheapest always-on Apple border router.
  • Apple TV 4K on Amazon — Apple's preferred always-on border router when it has Wi-Fi and Ethernet.
  • Nest Hub (2nd gen) on Amazon — Google's border router with a screen.
  • Nest Wifi Pro on Amazon — Wi-Fi 6E router and border router in one box.

Home Assistant Connect ZBT-2 is a different kind of border router: a USB radio for your Home Assistant machine, rather than a smart speaker that happens to include the feature. See below for what the Thread path looks like in Home Assistant.

One warning about "Built on Thread" packaging

Per Home Assistant's documentation, a device whose box shows the "Built on Thread: requires border router" logo is telling you something specific: Thread is the only supported protocol on that device — there is no Wi-Fi fallback. The Matter or Apple HomeKit logos on the same box indicate which protocol handles the credentials. So reading the logos correctly matters before you buy: a Thread-only device is fine, but it will not join your network if no border router is present, and you must know who holds the credential on an existing network.

Is Home Assistant itself a Thread border router?

Not out of the box, but it can become one. Home Assistant's Thread integration tracks the Thread networks in your home and stores their credentials — like a Wi-Fi password — so it can share them with phones, new hubs, or new border routers. You don't install the integration by hand; it appears automatically when Home Assistant detects a border router. The Home Assistant team says the integration is still a work in progress, and its Matter-on-Thread handling is likewise still in progress.

Turning Home Assistant into a border router means installing the OpenThread Border Router application, which drives a supported radio connected to the Home Assistant machine. One hardware note from the same documentation: Home Assistant hardware such as Connect ZBT-1, Connect ZBT-2, and Yellow ships running Zigbee rather than Thread, so enabling Thread involves manual steps. You are switching a capable radio to a different job, not plugging in something new.

Setting up: two starting points in the Thread panel

In Home Assistant, go to Settings > Connectivity > Thread. What you see there decides which path you take.

Case 1: no third-party Thread networks yet

Install the OpenThread Border Router app and Home Assistant creates a Thread network for you, named ha-thread-xxxx — the last four digits are the network's PAN ID. Confirm the Home Assistant logo appears under "Preferred network" so you know Home Assistant treats this as the network its devices should use.

Case 2: existing Thread networks, e.g. from a HomePod or Nest Hub

If a phone or another border router already has networks listed in the panel, you can bring those credentials into Home Assistant instead of creating a competing network. Per Home Assistant's Thread documentation, use "Send credentials to Home Assistant" in the Companion app (Settings > Connectivity > Thread), then "Make preferred network" so Home Assistant adopts the right one, and then install the OpenThread Border Router so Home Assistant's radio joins that existing network rather than forming a separate one.

Choosing between these two cases matters more than it looks. If you have both Google and Apple devices in the house, you can end up running multiple Thread networks side by side — each with its own credential. Thread itself can merge partitions across IP links, but you still have to decide which single network Home Assistant marks as preferred, or devices commissioned to it will join whichever mesh has the credential.

Sharing Thread credentials with your phone

Your phone needs Thread credentials before it can add new Matter-on-Thread devices, and the flow is different per platform:

  • iPhone: use Settings > Connectivity > Thread > Send credentials to phone.
  • Android: open the Home Assistant Companion app and use Settings > Companion app > Troubleshooting > Sync Thread credentials. It reports "Added network from Home Assistant to this device" when done.

This is the credential-sharing pain the Thread ecosystem still carries, and it's the reason the Thread integration stores credentials in the first place: Home Assistant effectively becomes the ledger of who knows what. If a new border router appears on the network — you plug in another HomePod mini, or buy a Nest Wifi Pro — Home Assistant will start listing it alongside the networks it already knows.

For a broader walk through planning a Thread network this way, see our Thread network guide.

Why several border routers, not one

Thread networks tolerate multiple border routers by design: the Thread-over-infrastructure feature merges partitions across your IP links, and OpenThread's documentation treats the border router role as infrastructural rather than exclusive. That is why Apple recommends the always-on Apple TV line as its preferred border router — battery-powered or intermittently-available routers create a network whose doorway opens and closes. Multiple always-on border routers give the mesh resilience and more radio coverage, at the cost of bookkeeping: every mesh that exists in your home should be visible in Home Assistant's Thread panel, and you should mark exactly one as preferred.

Troubleshooting

The Home Assistant Thread documentation covers the usual failure classes, and they are worth reading before buying a single new device: IPv6 issues (border routing requires IPv6 to flow on your home network), changing the Thread channel when it clashes with neighbouring networks or Wi-Fi, pairing failures, and reading OpenThread Border Router logs. Start at the integration's troubleshooting section before replacing any hardware — most pairing failures in this stack trace back to a credential the device never received, not a broken border router.

FAQ

What is a Thread border router, and do I actually need one?

A Thread border router is a device that connects a Thread mesh network to other IP-based networks such as your Wi-Fi or Ethernet. A Thread network needs one to reach anything outside its own mesh. If you run Matter devices over Thread with a phone, hub, or Home Assistant, you need at least one border router on the network.

Is Home Assistant itself a Thread border router?

Not by default. Home Assistant can become one when you install the OpenThread Border Router application, which turns a supported radio into a border router. Home Assistant hardware such as Connect ZBT-1, Connect ZBT-2, and Yellow ships running Zigbee, not Thread, so enabling Thread involves manual steps. Home Assistant's Thread integration with Matter is still a work in progress.

Which devices I already own are Thread border routers?

Apple devices include HomePod, HomePod mini, and Apple TV 4K models with Wi-Fi and Ethernet or Wi-Fi only (2nd and 3rd generation). Google devices include Nest Hub 2nd generation, Nest Hub Max, Nest Wifi, Nest Wifi Pro, and the Google TV Streamer. Nanoleaf and Amazon also sell border-router-capable devices, per Home Assistant's list.

How do I share Thread credentials with my Android phone or iPhone?

In Home Assistant, send credentials to a phone so it can commission Thread devices. On iPhone, go to Settings, Connectivity, Thread, then Send credentials to phone. On Android, in the Companion app go to Settings, Companion app, Troubleshooting, then Sync Thread credentials. Your phone needs the credentials before adding Matter-on-Thread devices.

Can I have more than one Thread border router, and what happens then?

Yes, and many homes end up with several. Home Assistant's Thread integration tracks the Thread networks in your home and stores their credentials, so you can see which networks exist and which one is preferred. The border routers merge Thread partitions over your IP infrastructure, so multiple routers make the Thread network more resilient, but you should decide which network Home Assistant treats as preferred.
