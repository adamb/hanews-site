OpenWrt Firmware Selector: check if your router is supported and get the right image

HA News · 16 Nov 2026

Before you put OpenWrt on a router you have two questions: does OpenWrt support this model at all, and which file do I download for it. The OpenWrt Firmware Selector answers both. It is a single-page web app: you type the model name, it shows the matching device profile with its target, the current version, the build date and the download links, and it links to the device's page on openwrt.org for the installation notes. The rule for which file to take is simple once you know it: a sysupgrade image if the router already runs OpenWrt, a factory image for the first flash from the vendor's own firmware.

The selector is also the safest source of truth. Download sites mirror OpenWrt images, but the selector reads OpenWrt's own build data, so what it lists for your model is what the project actually built. This guide walks through checking support, picking a version, telling factory from sysupgrade, and the customization options most people miss.

Step 1: check whether your router is supported

Go to firmware-selector.openwrt.org and start typing the model name exactly as printed on the case, for example "GL-A1300". The selector autocompletes against OpenWrt's device database. When your device appears, the result card shows four things: the model, the target (the SoC family and variant the build was made for, such as ipq40xx/generic or ath79/generic), the version you are looking at, and the build date.

If nothing shows up under your model name, the router is not in the official device list, which means there is no official build for it. Searching the exact hardware revision helps: vendors sell several revisions under one product name, and OpenWrt support is per revision, not per marketing name. Each device also has a dedicated page on openwrt.org (in the "Table of Hardware", at a URL of the form openwrt.org/toh/<vendor>/<model>) with install notes specific to that hardware, including any debricking steps. Always read that page before flashing.

The scale of support is worth knowing. OpenWrt's official per-release device list, refreshed this month, counts 2,187 devices with stable builds — and coverage of the current release is nearly total: 2,153 of those 2,187 devices have a build for the current stable release, 25.12.6, and 1,872 have a build for the previous stable, 24.10.8. A handful of devices only have builds in older releases, usually because their SoC support was removed or reworked.

Step 2: pick a version — stable, oldstable, or nothing

The selector defaults to the current stable release. As of 16 November 2026 that is OpenWrt 25.12.6, with 24.10.8 as oldstable; the release history goes back through 19.07. For a home router, take the current stable. It gets bug fixes and security updates, and the device profiles in the selector point at those builds by default.

A device listed in the device database carries a deep link straight into the selector with version, target and profile filled in. For the GL.iNet GL-A1300, for example, the link is firmware-selector.openwrt.org/?version=25.12.6&target=ipq40xx/generic&id=glinet_gl-a1300 — bookmark that form of link for your own model once you have found it, and you never have to search again.

If your device shows a build for 24.10.8 but not for 25.12.6, you face the ordinary tradeoff: an older stable release still receives maintenance updates for a while, but the device is not on current code. If a release you need does not appear at all, the selector offers a "Request build" button, which signals to the release engineers that someone wants that device in a given release.

One important exclusion: the selector also offers nightly "snapshot" builds. Snapshots are trunk builds for developers and testers. They do not include the LuCI web interface, they are not point releases, and they churn daily. For a router your house depends on, install the latest stable. If you want to know what is in the current stable release, see our OpenWrt 25.12 release notes.

Step 3: factory or sysupgrade — which image do you download?

This is the question the selector can't answer for you, because both files sit side by side in the same release directory. The naming follows a convention:

Your situationImage to useHow you flash it
Router runs the vendor's own firmwarefactory imageUsually through the vendor web interface: upload the image in the firmware-update page
Router already runs OpenWrtsysupgrade imageLuCI: System → Backup/Flash; or over SSH with the sysupgrade command, per the sysupgrade CLI documentation
Recovery / unbricking on some devicesinitramfs-kernel imageBooted into RAM without writing flash; used to recover or to bootstrap certain devices

The reason for two files is the firmware container. A factory image wraps the OpenWrt system in whatever container the vendor's own updater expects to accept — for GL.iNet's GL-A1300 in the 25.12.6 release that is a glinet_gl-a1300-squashfs-factory.ubi file, which the vendor update page accepts from stock firmware. The upgrade of an existing OpenWrt install on the same device is glinet_gl-a1300-squashfs-sysupgrade.bin. A sysupgrade image on a device running vendor firmware will be rejected; a factory image flashed over an existing OpenWrt install overwrites more than necessary and can leave you with a half-configured system. Match the file to the situation.

Note that a factory image does not exist for every device. On some SoC families — ath79 devices, for instance — the release directory only carries sysupgrade.bin and the initramfs image, because the vendor firmware on those devices expects the same container or is flashed through a different mechanism (a bootloader menu, TFTP, or a command-line tool). The device's page on openwrt.org documents the specific path for your hardware. The distinction between the two image kinds is what the project's own factory-and-sysupgrade guide is about.

Step 4: the flash, in short

  1. Confirm support in the selector and read the device's openwrt.org page for any model-specific steps.
  2. Download the right image kind (factory for first flash, sysupgrade for an OpenWrt-to-OpenWrt upgrade) for your hardware revision from the release directory the selector links to.
  3. For a first flash, follow the device page's instructions — commonly the vendor web UI uploading the factory image. Watch for vendor warnings about the exact revision.
  4. For an OpenWrt upgrade, back up your configuration first (LuCI → System → Backup/Flash, or sysupgrade -b over SSH), then flash the sysupgrade image. The same CLI guide covers keeping or dropping settings.
  5. After the first flash, set a password, and connect to LuCI over http://192.168.1.1 (or whatever the device page says the default address is) to configure.

If you have not yet chosen hardware, our best OpenWrt routers roundup lists devices with official builds across the current releases, so everything there works end-to-end with the selector.

Customizing the image: packages and first-boot scripts

Two optional features in the selector are worth knowing about, because they change the flash-once-configure-forever experience:

  • "Customize installed packages": the selector lets you edit the package list that goes into the image. If you know you always install WireGuard or a specific USB driver, baking it into the image avoids a reinstall after every reflash.
  • First-boot script (uci-defaults): you can attach a script that runs on the first boot, applying UCI configuration — setting a password hash, disabling unused services, pre-seeding network settings. It makes reflashing a router reproducible instead of a click-through exercise.

Both are optional; the defaults produce a normal, clean OpenWrt image. They are most useful when you maintain several routers of the same model and want them identical after a flash.

Gotchas worth knowing before you flash

  • Support is per hardware revision. Two boxes with the same product name can be different devices inside. The selector's autocomplete lists the revision strings — pick the one that matches the label on your unit, not just the model line.
  • Don't install a snapshot on a production router. The nightly trunk builds lack LuCI and are for development. The stable release exists precisely so you don't have to run trunk.
  • Match image kind to current firmware. Factory image for vendor firmware; sysupgrade image for an existing OpenWrt install. Downloading the wrong kind is the most common first-flash failure.
  • Read the device page first. Some devices need a specific order of steps (an initramfs boot before a sysupgrade, a bootloader unlocked with a vendor tool, an antenna swap, or a serial connection to recover). The openwrt.org Table of Hardware page for your model is the checklist.
  • Version freshness. The release list moves; current stable is 25.12.6 (oldstable 24.10.8). If the selector shows something newer, trust the selector — it reads OpenWrt's own version feed.

FAQ

How do I find out if my router is supported by OpenWrt?

Open the Firmware Selector at firmware-selector.openwrt.org, type your router's model name, and see whether an official build appears. If it does, the page links straight to the download for your hardware revision. The model's page on openwrt.org has install notes.

What is the difference between a factory and a sysupgrade image?

A factory image is for the first flash from the vendor's own firmware, usually through the vendor's web interface. A sysupgrade image is for upgrading or reinstalling a router that already runs OpenWrt, either from the LuCI web interface or with the sysupgrade command over SSH.

Is there a 25.12.6 image for my device?

For most supported devices, yes. Of the 2,187 devices with official builds in OpenWrt's device list, 2,153 have a 25.12.6 build. The Firmware Selector shows which version is available for your model.

How many devices does OpenWrt support?

OpenWrt's official device list counts 2,187 devices with stable-release builds. 2,153 of them have a build for the current stable release 25.12.6, and 1,872 have one for the previous stable 24.10.8.

Can I use the Firmware Selector to customize installed packages?

Yes. The selector offers an optional "Customize installed packages" section and a first-boot script (uci-defaults) field, so the image it produces can include the packages and settings you want from the first boot.

What is the OpenWrt snapshot build and should I install it?

Snapshots are nightly trunk builds for developers. They do not include the LuCI web interface and they are not point releases. For a home router, install the latest stable release instead, which is 25.12.6.
