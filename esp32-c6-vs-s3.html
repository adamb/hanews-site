ESP32-C6 vs ESP32-S3: which chip for ESPHome and Matter (2026)

HA News · 13 Nov 2026

ESP32-C6 vs ESP32-S3 comes down to one question: does your build need a Thread or Zigbee radio, or does it need muscle? The ESP32-C6 is the chip with the 802.15.4 radio — Thread and Zigbee 3.0 alongside Wi-Fi 6 — so it is the ESP32 to pick for Matter-over-Thread end devices, connected lights and switches. The ESP32-S3 is the faster, camera-and-voice chip: dual cores up to 240 MHz, a camera interface and AI vector instructions, but no Thread or Zigbee radio at all. Both are first-class ESPHome platforms, so the choice is about hardware, not software support.

Radio differences: this is the whole ballgame

Per the ESP32-C6 datasheet, the C6 carries a 2.4 GHz Wi-Fi 6 (802.11ax) radio, Bluetooth 5 (LE), a native 802.15.4 PHY for Zigbee and Thread. That is four radios on one chip, with datasheet-documented transmit and receive characteristics for the 802.15.4 side. It also means a single ESP32-C6 board can be a Wi-Fi sensor today and a Thread device tomorrow, with only a firmware change.

Per the ESP32-S3 datasheet, the S3 has Wi-Fi and Bluetooth 5 LE — and that is it. There is no 802.15.4 PHY, so no native Thread and no native Zigbee. If a project spec says "Matter over Thread", the S3 is out. The closest it gets is Matter over Wi-Fi only.

Why it matters: Thread is where Matter home networks are heading, and a border router plus Thread devices gives you a low-power, self-healing mesh that survives a Wi-Fi outage. If you plan devices for a Thread network — or you want your DIY gear to behave like commercial Matter accessories — the C6 is the only one of these two chips that can. For what a Thread network looks like in a real house, see our Thread border router coverage.

CPU and memory: the S3 wins on paper

The C6 runs a 32-bit RISC-V processor with a four-stage pipeline clocked up to 160 MHz, plus a separate low-power RISC-V processor up to 20 MHz that stays alive in deep sleep; Espressif notes the LP processor can even keep the Wi-Fi connection offloaded in deep-sleep scenarios. Memory is 512 KB of HP SRAM for data and instructions, per the datasheet. That is plenty for a sensor node reporting temperature to Home Assistant.

The S3 is a different class of machine: a dual-core 32-bit Xtensa LX7 microprocessor, configurable up to 240 MHz, with 384 KB of SRAM in its memory tables and documented PSRAM options for bigger buffers. Espressif markets the S3 as the AI chip — its extension set includes vector instructions for signal processing and inference. If your firmware is doing work on the chip (microWakeWord-style wake words via ESPHome's voice assistant pipeline, camera frame processing, display driving), the S3 has the headroom and the C6 does not.

One C6 caveat worth repeating: it has no camera (DVP) interface and none of the S3-style AI/vector instructions. Keep heavy signal processing off this chip — it is a radio-first, low-power part, not a performance part.

ESPHome support: both are first-class

ESPHome treats both variants as the same platform. In the esp32 component documentation, variant: esp32c6 and variant: esp32s3 are both valid values of the same esp32 component (the full list also covers esp32, s2, c2, c3, c5, c61, h2, h4 and p4). In practice you set the variant, and a standard ESP-IDF devkit board definition is filled in for you; flash size offers 2 to 32 MB with a 4 MB default, and at least one of board or variant must be present in your YAML.

Typical minimal config on either chip:

esp32:
  variant: esp32c6 # or esp32s3
  flash_size: 4MB

Both run on the ESP-IDF framework in ESPHome, and both flash through the same USB-serial flow as any other ESP32 board. The one hard rule: the variant must match the hardware you actually soldered in, or the flash fails. There is no penalty for picking the "wrong" one in YAML — the build just refuses.

Where the chips differ inside ESPHome is in what components they can host. The Thread/Zigbee side of the C6 maps to ESPHome's 802.15.4 support for Matter-style end devices; the S3's camera and audio pipelines map to the voice assistant and camera components. Both chips do Wi-Fi, BLE, sensors, relays, displays and the usual ESPHome suspects. For build ideas that work on either family, see our ESP32 projects guide.

Matter: C6 is a Thread device; S3 is Wi-Fi only

Matter runs over Wi-Fi, Ethernet, and Thread. The C6 covers two of those three transports on one chip: Espressif lists Matter, HomeKit and MQTT among the protocol stacks it supports, and because of the 802.15.4 radio a C6 board can present itself as a Thread device — or as a sleepy end device, if you want battery-friendly operation. That is the profile most DIY Matter accessories want: slow-talking, low-power, mesh-routed.

The S3 can only do Matter over Wi-Fi, if at all. It is fine for a powered Wi-Fi IoT gadget, but it cannot join a Thread mesh, and it cannot act as a low-power sleepy end device on one. If your Home Assistant network routes through a Thread border router, every S3 device you add is a device on the Wi-Fi side instead — more traffic on the wireless LAN, nothing on the mesh.

Gotchas

  • Variant mismatch kills the flash. ESP-IDF must be told the right chip; the ESPHome docs are blunt that the variant must match the hardware in use or flashing fails.
  • The C6 is not a border router. It can be a Thread end device, but a 160 MHz part with 512 KB SRAM is a radio node, not the always-on mesh router at the heart of your network. For that job Home Assistant uses a proper Thread border router — see our Thread border router explainer.
  • Don't buy an S3 for Thread. No 802.15.4 radio, no workaround inside ESPHome. If the project name contains Matter plus Thread, it needs a C6 (or an h2/c-class 802.15.4 chip — the ESPHome variant list includes h2 and others).
  • Don't buy a C6 for a camera. There is no DVP interface, and no vector instructions to make up for it.
  • 2.4 GHz only on both chips. Neither is a 5 GHz device. Plan your IoT VLAN and channel choices accordingly.

Setup steps (either chip)

  1. Plug the devkit into your workstation over USB. Both chips' USB-serial appears as a serial port; the S3 additionally has a full-speed USB OTG interface with integrated transceiver, so its USB port can also act as device-mode USB (a USB Serial/JTAG peripheral).
  2. Install ESPHome (standalone, or as the Home Assistant add-on).
  3. Create a new device and set the variant line — esp32c6 or esp32s3. Leave board unset at first; ESPHome fills in the standard ESP-IDF devkit for the variant.
  4. Build and flash over USB-serial, or use ESPHome Web for browser-based flashing.
  5. Bring the device onto your network. For a C6 Matter-over-Thread device, commission it against your Thread network's credentials; for Wi-Fi, the usual ESPHome provisioning flow.
  6. Add sensors/actuators, deploy, and verify state in Home Assistant.

FAQ

Does the ESP32-C6 work with Thread and Matter in ESPHome?

Yes. The ESP32-C6 has a native 802.15.4 radio for Thread and Zigbee 3.0, and Espressif lists Matter among its supported protocol stacks, so a C6 board can act as a Thread device on your Matter network.

Can the ESP32-S3 run Thread or Zigbee?

No. The ESP32-S3 has Wi-Fi and Bluetooth LE only, with no 802.15.4 radio, so it cannot run Thread or Zigbee natively. An S3 device joins Matter over Wi-Fi, if at all.

Which ESP32 is better for camera projects — C6 or S3?

The S3. It has a DVP camera interface with the image sensor clock up to 40 MHz, plus vector instructions for on-device processing. The C6 has no camera interface.

Is the ESP32-C6 good for voice assistants?

Not really. Espressif positions the S3 (dual-core LX7 up to 240 MHz, vector instructions) as the AI and voice chip, and ESPHome Voice Assistant-class hardware uses S3-class audio pipelines.

Which ESP32 should I use for an ESPHome device on a Thread network?

The ESP32-C6. It is the ESPHome chip with a native Thread radio; the S3 has no 802.15.4 radio at all.

Does ESPHome support the ESP32-C6?

Yes. ESPHome's esp32 component supports the C6; set variant: esp32c6 in your YAML and a standard ESP-IDF devkit board is filled in for you.
