Meshtastic vs MeshCore: which LoRa mesh for off-grid texting (2026)

HA News · 11 Nov 2026

Both projects answer the same question: how do you send text messages where there is no cell service — a ranch gate, a boat, a mountain cabin, a hurricane-hit neighborhood — without paying for satellite messaging. The answer each gives is a mesh of cheap LoRa radios. Each radio rebroadcasts what it hears, so messages hop node to node over miles of open terrain using unlicensed spectrum that needs no ham radio license. The difference is in how each project builds that mesh. Meshtastic is the larger, more mature project with polished phone apps and automatic rebroadcast routing; MeshCore is a newer, deliberately lighter-weight alternative with fixed node roles and dedicated repeater hardware. This page compares routing, apps, hardware and flashing, then helps you pick.

What Meshtastic is

Meshtastic is an open-source project built around one idea: a radio receives a message and rebroadcasts it, and every router-capable node in range does the same, so the text propagates across the mesh without any central server. The project documents a 331 km long-distance record for a LoRa hop. A phone connects to a node over Bluetooth or USB to compose and read messages; each device supports connection from only one phone or user at a time, which is worth knowing if a household shares one node. Nodes can carry optional GPS so positions appear alongside chat. Because Meshtastic runs on unlicensed LoRa spectrum, no license is required — unlike ham-radio digital networks. The project is community-driven, and the docs point out that no dedicated router node is required to make a mesh work: ordinary nodes carry traffic. The project's introduction page lays this out in full.

Meshtastic ships frequent firmware releases. The latest release at the time of writing, v2.7.26.54e0d8d (Beta), published 24 June 2026, was mostly bug fixes plus new board configurations — RAK 6421/13300/13302 variants, Zebra/Nebra hats, the B&Q Station G3, T-Deck touch calibration, and continued work on meshtasticd, the Linux-native build for boards that run Linux rather than an RTOS. That pace is typical: board support arrives as vendors ship new trackers and hats.

What MeshCore is

MeshCore is a newer project from the same hobby. It is a lightweight C++ library for multi-hop packet routing on LoRa packet radios, under the MIT license, hosted at meshcore-dev/MeshCore (roughly 4,000 stars and 1,600 forks). The README positions it explicitly: designed to balance simplicity against Reticulum's advanced networking, and lighter-weight than both Meshtastic and Reticulum. Where Meshtastic treats almost every mains-powered node as a potential router, MeshCore gives every node a fixed role, and the role is baked into the firmware you flash.

  • Companion — the radio paired with your phone's client app. Companion nodes never repeat messages. That single rule is MeshCore's biggest design difference.
  • Repeater — a headless node that does the hopping. Administered by serial console or password. A "hidden" mode keeps a repeater out of node lists when its adverts are off (undiscoverable as of v1.18.0).
  • Room Server — a headless node that stores and serves channel messages, like a bulletin board on the mesh. Access is password-controlled.

Hop limit is configurable, and the project's FAQ documents the mesh behaviors you will actually tune: adverts, path hashes, repeater deafness. The MeshCore docs cover the CLI commands, the Companion Protocol, the packet and payload format, radio presets, QR-code provisioning and the Terminal Chat CLI.

Routing compared: automatic mesh vs fixed roles

This is the heart of the meshtastic-vs-meshcore question. In Meshtastic, you deploy nodes and the mesh largely organizes itself: messages rebroadcast through router-capable roles, no dedicated router is required, and adding a node generally extends coverage without configuration. The trade-off is that every participating node carries traffic, so airtime is shared among everything in range — on a crowded channel, rebroadcasts from devices you never intended to be infrastructure consume the channel.

In MeshCore, you decide explicitly where the mesh is. Companion nodes — everything a person carries or keeps on a desk — never repeat, so your pocket radio stays quiet and saves battery. Only the Repeaters you deliberately placed, typically mounted high with good antennas, forward traffic. For a planned installation — a farm with two towers, a camp with a mast on the ridge — that control is the appeal: you know exactly which radio is doing what, and you can set the hop limit per design rather than watch it converge. The cost is that MeshCore won't build a mesh by accident out of whatever nodes happen to be switched on; if no Repeater is placed between two Companions, they don't talk beyond direct radio range.

Apps and clients

Meshtastic's phone apps are the most mature part of the project. You pair a phone to a node, chat, see node lists and positions, and administer settings from the app. The constraint to plan around is the one-phone-per-device rule documented by the project.

MeshCore's model separates the radio from the client. The Companion radio pairs with phone client apps; the docs also include a Terminal Chat CLI for keyboard-driven use over serial, which suits a headless laptop or a fixed terminal at a base camp. Repeaters and Room Servers are administered by serial console or password, not by the chat app — infrastructure and conversation are deliberately kept apart. In the most recent release, Companion Firmware v1.18.0 (15 October 2026), the project added a Companion CLI with commands like tz.offset get/set, wifi configuration, and reboot/poweroff; sensor telemetry push/subscribe; RAK12500/12501 GPS support on the RAK3401; thermal fan control on the T-Beam-1W; a repeater loop-detection default; and new device support for the Thinknode M8/M6/M4, WIO Tracker L1 1W, Muzi Base boards, and the Waveshare ESP32-S3 LR1121.

Hardware, and the one check that matters before buying

Both projects run on widely available LoRa boards, and both support the Heltec V3, the RAK4631, the LilyGo T-Deck and T-Beam family, and assorted outdoor trackers. Meshtastic additionally documents long lists of supported hardware and frequent new-board configs in its release notes, including Linux-native boards via meshtasticd. MeshCore's support list skews to the same popular ESP32 and nRF52 boards, with new trackers added release by release (the Thinknode and WIO Tracker L1 above, for example), and the docs cover nRF52 power management, which matters for battery-powered repeaters.

Before you buy, cross-check the exact board you are looking at against both projects' device pages. Meshtastic support does not guarantee MeshCore support and vice versa. A board that is first-class in one project may be missing, experimental, or absent in the other. This is the single most common way to end up with a radio you cannot flash for the network you joined.

Flashing: both are point-and-click

Neither project requires you to compile firmware. Meshtastic provides a web flasher at flash.meshtastic.org; MeshCore provides pre-built binaries flashable through Adafruit ESPTool at its own flasher, and lists board-specific flashing instructions in the docs. The general procedure for either: plug the board in over USB, pick your board and firmware variant in the web flasher, flash, then configure region and role. Switching a board from one project to the other is the same operation — flash the other firmware — losing whatever configuration and node database the previous firmware held, not the hardware.

Building a first mesh with MeshCore

Because roles are flashed rather than assigned, plan the roles before you buy or flash. Three deployments cover most cases:

  • a radio for the gate or the dock: one Companion radio and your phone;
  • coverage across a property: two or three Repeaters, one at the house, one at the far end;
  • a channel your group can read later, or an off-grid "inbox": a Room Server.

Because companions never repeat, a single-node Meshtastic-style setup (one node, one phone, direct range only) works fine in MeshCore too — you just have no mesh. Where the projects differ is what happens as you grow.

Which to pick

Pick Meshtastic if you want the larger community, the most mature phone apps, and a mesh that forms itself as friends and neighbors add nodes. It suits ad-hoc groups, event networks, and a community channel where you can't control which hardware joins. If your goal is a neighborhood resilience network you don't administer centrally, Meshtastic's rebroadcast-everything design is a feature, not a bug.

Pick MeshCore if you are planning a fixed network — a property, a farm, a valley with two good tower sites — and you want to decide exactly which radios spend airtime repeating. Companion nodes staying out of the mesh keeps personal radios quiet and saves battery; the Repeater and Room Server roles give you infrastructure you can administer deliberately. It is also the lighter codebase, if simplicity is the priority.

Both are open source, both run on the same class of cheap LoRa hardware, and both use unlicensed spectrum with no license required. The mesh you can maintain is worth more than any feature list: if your fellow node operators already run one project, stay with it.

FAQ

MeshCore vs Meshtastic: which is better for off-grid text messaging?

Both send long-range text over unlicensed LoRa radio with no cell coverage. Meshtastic is the older, larger project with mature phone apps and automatic rebroadcast routing. MeshCore is a newer, lighter-weight project with fixed node roles and dedicated repeater and room-server node types. Pick Meshtastic for community mesh and app polish; pick MeshCore if you want simple, role-based control of what repeats.

Can a Meshtastic node also run MeshCore firmware, or do I need separate radios?

The same LoRa board can usually run either firmware, because both projects support popular boards such as the Heltec V3 and RAK4631, but it runs one at a time and you reflash to switch. Check each board against both projects' firmware pages before buying: Meshtastic support does not guarantee MeshCore support and vice versa.

Which has better range, Meshtastic or MeshCore?

Range depends on the radio hardware, antenna and terrain, not the firmware. Meshtastic documents a 331 km long-distance record. MeshCore supports the same class of LoRa hardware, including 1-watt trackers. Neither project changes the physics of LoRa at the legal power limits.

How many nodes do I need to start a MeshCore mesh?

At minimum, one Companion radio paired with your phone's client app. Text only reaches phones and room servers other nodes hop to, so a useful mesh also has at least one Repeater, usually placed high, and optionally a Room Server for stored messages. Companion nodes themselves never repeat messages.

Do Meshtastic and MeshCore interoperate on the same frequency?

No. They use different packet formats and routing, so a node running Meshtastic cannot decode or repeat MeshCore traffic, or the reverse. Nodes in one mesh must all run firmware from the same project.
