Best LoRaWAN sensors for a rural property (tank, gate, freezer, soil)

HA News · 13 Nov 2026

Wi-Fi, Zigbee and Z-Wave sensors stop being practical once the sensor is 100 meters from the house, or at the end of a long driveway with no repeater in between. That is the job a LoRaWAN sensor is built for: a battery-powered node that wakes up, transmits a few bytes on an 868 or 915 MHz radio, and goes back to sleep. Range is measured in kilometers, batteries are designed to last years, and the sensor needs nothing from your network. For most rural jobs the answer is a ready-made LoRaWAN end device — a Milesight EM400-UDL for a water tank, an EM300-MCS for a gate or mailbox, a TS301/TS302 for a freezer, or a Dragino LSN50v2-S31 for soil — reporting through The Things Network into Home Assistant over MQTT. This page explains how those sensors work, how to get the data into Home Assistant, and where each model fits.

If you don't yet have the receiving side, start with how to pick and set up a LoRaWAN gateway; a sensor without a gateway is a very quiet investment. And if the job is specifically tank level, we went deeper in water tank level sensors.

What a LoRaWAN sensor is (lora sensor vs LoRaWAN sensor)

The two terms get swapped freely, so pin them down once. LoRa is the physical radio: a modulation technique that trades data rate for range and sensitivity, so a few bytes can travel for kilometers on milliwatts. LoRaWAN is the network protocol defined on top of that radio — it specifies how a device joins a network, identifies itself, encrypts payloads, and negotiates data rates. A "LoRa sensor" might use the radio with a private protocol point-to-point; a LoRaWAN sensor speaks the standard, which is what lets it onboard into a multi-vendor network like The Things Network. When you buy, you want a device that speaks LoRaWAN, not just LoRa, unless you plan to build your own receiver.

The network matters for another reason: onboarding. The Things Network's device repository is the database The Things Stack uses to register a device — per-vendor profiles, hardware versions, and payload codec definitions. If a sensor has a proper entry there (or you use a generic profile and supply a decoder yourself), you can onboard it cleanly. The repository's README describes it as the catalog of LoRaWAN devices for The Things Stack. Before buying any node, check it exists in that repo or that the vendor supplies a payload codec.

How LoRaWAN sensors get data into Home Assistant

There is no native "LoRaWAN" integration in Home Assistant as of this writing, and there isn't one on home-assistant.io. The working path runs through MQTT, and it is genuinely local-first if you self-host the stack:

  1. Sensor to gateway. The battery sensor transmits an uplink to your LoRaWAN gateway. Per The Things Network's documentation, the gateway is just radio hardware that forwards packets.
  2. Gateway to The Things Stack. Packets go to The Things Stack — either The Things Network's hosted community stack (free, but it is a cloud service) or your own TTS instance (fully local).
  3. Decode the payload. Sensors don't send JSON; they send binary. TTS applies the payload codec from the device repository — or the vendor's decoder — to turn bytes into readable fields.
  4. MQTT into Home Assistant. TTS publishes the decoded JSON to an MQTT topic. The standard setup pairs the Things Stack MQTT feature with the Mosquitto broker and Home Assistant's MQTT integration, which watches the topic and creates entities.

Because TTS stores device keys and applies codecs, each sensor type needs its payload decoder — the lorawan-devices repository carries codec definitions per vendor, which is most of the integration work already done for you.

Pick by job: the sensors that fit a rural property

These are not the only LoRaWAN sensors on the market, but each exists in the TTN device ecosystem, is documented by its manufacturer, and maps to a job where long range and years of battery life are the point. No prices here; check current listings on Amazon.

Water tank level: Milesight EM400-UDL

For a cistern or rain tank, the Milesight EM400-UDL is an ultrasonic distance and level sensor. It measures the distance to the water surface — no submerged probe, nothing to corrode or foul — and reports level over LoRaWAN. Non-contact sensing is the practical advantage for a tank you'd rather not open regularly, and the unit is built for outdoor deployment. If the tank has a narrow access pipe instead of an open top, Milesight makes the EM500-SWL submersible water level sensor, which goes inside the pipe and measures pressure instead of distance. For the full picture, including DIY alternatives, see water tank level sensors.

Gate, mailbox, and door open/close: Milesight EM300-MCS

A long driveway usually means you learn about a delivery when you walk down and look. The Milesight EM300-MCS is a battery-powered magnetic contact switch: it reports open and closed over LoRaWAN, the same job a Zigbee door sensor does on your front door, at radio range instead of room range. Stick the magnet half on the gate leaf and the body on the frame. The same family covers leaks — Milesight's EM300-MLD and EM300-SLD are leak-detection siblings — and a pulse-counter (EM300-DI) and tilt sensor (EM320-TILT) sit in the same product line for jobs like counting pump cycles. Check the EM300-MCS on Amazon.

Freezer and cold storage: Milesight TS301 / TS302

A chest freezer in a detached building is the classic silent failure: nobody notices a bad compressor until the smell does. The Milesight TS301 and TS302 temperature sensors are LoRaWAN loggers built for cold storage. The features worth knowing about, per the product documentation:

  • IP65 housing and low-temperature operation, with an optional food-grade probe.
  • Up to 10,000 stored history records with retransmission. If your gateway or internet link goes down, the sensor keeps logging and uploads the gap when it can reach the network again. For freezer monitoring this is the feature that matters — an outage does not blind you.
  • Instant temperature-alert uplink when the reading crosses a threshold.
  • Milesight D2D (device-to-device) support: the sensor can directly trigger another Milesight LoRaWAN device without a gateway in the loop — for example, ringing a local alarm on high temperature. Per Milesight's documentation, D2D works alongside normal LoRaWAN uplinks.
  • NFC configuration through the vendor's ToolBox app, firmware update over the air, and EN12830 certification for food cold-chain use.

Check the TS301 on Amazon and the TS302 on Amazon.

Soil moisture and temperature: Dragino LSN50v2-S31

For garden beds, orchards, or a pumphouse you want to keep an eye on, the Dragino LSN50v2-S31 is a soil moisture and temperature node in the LSN50v2 line of battery LoRaWAN end devices. Dragino's wiki (the company routes product detail through wiki.dragino.com, with "user manuals and quick start guides for all Dragino LoRaWAN sensor nodes") documents the sensor, gateway configuration, and The Things Network and ChirpStack integration guides in one place. Alternatives in the same family include other LSN50v2 variants and SenseCAP's S2100-series soil sensor — verify the exact model and its payload codec in the TTN device repository before committing. Range and placement: the honest physics

Manufacturers like to quote maximum range figures. What actually determines whether your mailbox sensor reaches the gateway is line of sight. A flat stretch of pasture at 868/915 MHz with tall antennas on both ends will do kilometers. A sensor inside a steel mailbox half a meter off the ground behind a wall of vegetation will not. Dragino's knowledge base — which covers antenna selection and power management specifically — is the vendor reference worth reading before you plan, because its advice is blunt: antenna height and placement matter more than transmit power, and the sensor-side antenna placement usually matters more than the gateway's.

Practical consequences: mount the gateway antenna as high as you legally and structurally can; prefer sensors with accessible external antennas for indoor placements such as a freezer; and test with one sensor before buying five. One gateway covers most rural properties, but trees are water, and water is not your friend at sub-GHz frequencies either — it attenuates, wet-season performance can be worse than dry-season.

Battery life in real use

LoRaWAN sensor batteries are designed around a simple budget: a few-millisecond transmit burst, a few times a day. Vendors design these nodes for years on small cells at default reporting intervals. Nobody should promise you a number without context, though. Three variables dominate:

  • Reporting interval. A level sensor checking every 10 minutes versus every hour is roughly a multiplier on one of your two big costs. Match the rate to the risk: tank level hourly is plenty; a gate contact needs to report events, which it does anyway on change.
  • Spread factor. A sensor at the far edge of your gateway's range uses a higher spread factor, which means longer airtime per uplink, which means more battery per message. Placing the gateway generously buys battery life everywhere.
  • Temperature and chemistry. A freezer sensor's battery works hardest in exactly the coldest jobs; note what the manufacturer says about operating range and pick models rated for the installation environment.

The conservative planning move: pick the reporting interval you'd accept if the battery lasted half as long as the datasheet suggests, and enable any vendor retransmission buffer so a gateway outage doesn't cost you data (the TS30x does this; see above).

Gotchas before you buy

  • Region matters. 868 MHz (EU) and 915 MHz (US) hardware are not interchangeable. Buy for your region's frequency plan and select it in The Things Stack.
  • Check the device repository first. A sensor without an entry in the TTN lorawan-devices repo and no vendor codec means you're writing your own decoder.
  • The hosted TTN community stack is a cloud service. If local-only matters to you, self-host The Things Stack (or run ChirpStack, which LoRaWAN sensors generally also support) so payloads never route through someone else's servers. Milesight devices also target Milesight IoT Cloud and the company's own gateways, but for a Home Assistant-first setup the TTN/ChirpStack-plus-MQTT path is the one that keeps data in your hands.
  • Not every "smart" Milesight device is LoRaWAN. The VS-series people counters (VS133, VS125, VS126) do not have LoRaWAN versions — don't try to onboard them into a LoRa network.
  • Gateways are the prerequisite. A LoRaWAN sensor without a gateway in range just drains its battery quietly. Sort out coverage before the sensors, not after.

Setup steps, end to end

  1. Stand up the receiving side first — gateway, The Things Stack (self-hosted or the community network), Mosquitto, and Home Assistant's MQTT integration. The gateway guide covers the choices.
  2. Find your sensor in the TTN device repository and note its hardware version and JoinEUI-style registration details from the label or the vendor page.
  3. Register the device in The Things Stack with the correct region frequency plan and the profile from the repository.
  4. Power it up, trigger a reading (press the button, open the contact), and confirm the uplink arrives and decodes with human-readable fields in TTS.
  5. Point TTS's MQTT subscription at Mosquitto and create Home Assistant entities from the observed fields — the payload codec already did the hard part.
  6. Build the automations: a tank-level alert below a threshold, a gate contact notification, a freezer temperature above minus-15 for two readings, whatever your property needs.

FAQ

How far do LoRaWAN sensors reach in a rural property?

It depends on line of sight more than transmit power. In open rural terrain, kilometers are common; buildings, foliage and antenna placement cut that fast. Dragino's knowledge base on antenna selection is the vendor doc to read before deciding where a gateway and sensors go.

Do LoRaWAN sensors work with Home Assistant directly, or do I need The Things Network?

There is no LoRaWAN integration in Home Assistant as of this writing. Sensors report to The Things Stack (The Things Network or a self-hosted stack), which forwards decoded JSON over MQTT to Mosquitto, and Home Assistant picks it up with its MQTT integration.

Which LoRaWAN sensor should I use for a water tank, a gate, or a freezer?

Tank level: a non-contact ultrasonic sensor such as the Milesight EM400-UDL, or an in-pipe submersible like the EM500-SWL. Gate or mailbox: a magnetic contact switch such as the EM300-MCS. Freezer: a low-temperature logger such as the Milesight TS301/TS302, which keeps a history buffer and retransmits after an outage.

How long do LoRaWAN sensor batteries last in real use?

Vendors design these nodes for years on small batteries because the uplinks are short and infrequent, but real battery life depends on reporting interval, spread factor and temperature. Check the datasheet for the specific model and be conservative on your report rate.

Can a LoRaWAN sensor trigger an HA automation without a gateway (D2D)?

Some Milesight sensors support Device-to-Device (D2D) communication, where one sensor can directly trigger another LoRaWAN device without a gateway in the loop. D2D covers the radio-to-radio trigger; the data still reaches Home Assistant through The Things Stack and MQTT when a gateway is present.

What's the difference between a lora sensor and a LoRaWAN sensor?

LoRa is the radio modulation the sensor uses to send data over long distances at low power. LoRaWAN is the network protocol on top of it that defines how devices join, communicate and are managed. A LoRaWAN sensor speaks both; a bare "LoRa" sensor may use a private protocol instead.
