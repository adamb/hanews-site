OpenWrt on x86: turn a mini PC into your router (2026)

HA News · 16 Nov 2026

You do not need a "supported router" to run OpenWrt. OpenWrt publishes generic builds for x86, the same instruction set as a desktop PC, laptop or mini PC, so any 64-bit Intel or AMD machine can become your router by writing one image to disk. The current stable release is 25.12.6 (released 18 October 2026) and the oldstable branch is 24.10.8 (released 26 July 2026, with many security fixes). This guide covers which image to pick, which hardware makes sense, and the gotchas — including the biggest one: an x86 OpenWrt box has no Wi-Fi, so you pair it with a separate access point and keep the router and your Home Assistant box as two machines.

Why run OpenWrt on x86 at all

Most OpenWrt setups run on consumer Wi-Fi routers, where the CPU is the constraint. An x86 box inverts the trade: you get a real desktop-class processor, gigabytes of RAM and proper Ethernet silicon, and you give up built-in wireless. For a smart home that choice is defensible. The router's job — NAT, firewall rules, WireGuard or Tailscale for remote access, an IoT VLAN for your Home Assistant network — is mostly CPU and packet forwarding, and a mini PC has far more headroom than a sub-$200 router's SoC.

Support also works differently. On consumer routers, OpenWrt needs a per-model build assembled for that exact board. On x86 there is a generic x86/64 target ("Generic x86/64" in OpenWrt's device table) that covers any 64-bit PC: one image, no model match, no firmware selector archaeology. OpenWrt currently supports four x86 subtargets: x86/64 for modern 64-bit machines, x86/generic for 32-bit hardware, x86/geode for AMD Geode boards including Traverse Geos, and x86/legacy. In practice you will use x86/64. More background on which system to choose is in our OpenWrt guide.

Which image to download

For OpenWrt 25.12.6, the x86/64 download index at downloads.openwrt.org — targets/x86/64 lists these images (build dated 18 October 2026, SHA256 sums published on the same page):

  • generic-squashfs-combined-efi.img.gz — for UEFI boot. This is the one most modern mini PCs need (~12.2 MB).
  • generic-squashfs-combined.img.gz — for legacy BIOS boot on older machines.
  • Ext4 variants of both, and a rootfs.tar.gz for running OpenWrt in containers or chroots.

Picking the wrong one is the classic mistake: an EFI image will not boot on a BIOS-only board and vice versa. If unsure, boot the machine's firmware setup first and look at which boot mode is listed. The firmware selector builds the same links per target — for example the x86/64 generic build. The other subtargets have their own selector entries: x86/generic and x86/geode, the latter covering Traverse Technologies Geos boards as well.

  1. Download the image and its SHA256 sum; verify the hash before flashing.
  2. Connect the target machine to your network, and have a second wired connection or a serial console for first-time setup.
  3. Write the image straight to the target SSD or USB drive with dd or a flashing tool such as Etcher. Do not try to install it into a running OS — it is a whole-disk image.
  4. Boot, then point a browser at the default address OpenWrt prints on its console and set up LAN, WAN and your firewall zones.

Hardware picks

OpenWrt only publishes per-model builds for a handful of x86 systems (the Traverse Geos boards, for example). Everything else is covered by the generic target, so the honest claim for any mini PC listed below is "runs the generic x86/64 target", not "listed in the Table of Hardware". Specs below come from the manufacturers' pages.

Protectli Vault 4-port

Protectli's Vault 4-port line is built for exactly this role: a fanless quad-core appliance with a choice of Intel N150, J3160, J3710, J4125, N5105 or J6412 processors, up to 32 GB DDR4 (or 64 GB DDR5 on newer boards), and 1GbE, 2.5GbE or SFP+ NIC options. Protectli ships coreboot firmware and states the Vault is OS-agnostic — OpenWrt and OPNsense both run on it. AES-NI is supported across the line, which matters for WireGuard throughput on your remote-access tunnel. Four Ethernet ports give you WAN, LAN and an IoT VLAN without a managed switch. Check Protectli Vault on Amazon for current options and stock, and read Protectli's own spec page before picking a CPU. Not sure OpenWrt is your system? Our OpenWrt vs OPNsense comparison covers the same hardware.

PC Engines apu2

The apu2 is the classic budget board for this job: an AMD GX-412TC quad-core 1 GHz Jaguar SoC with AES-NI, 2–4 GB of DDR3, two or three Gigabit Intel i210AT/i211AT NICs, coreboot BIOS and a fanless 6×6-inch board drawing roughly 6–10 W. It boots from m-SATA, SD or USB. Two caveats from the manufacturer: the AMD SoC is at end of life after a long production run, and 2 GB RAM models are tight once you add OpenWrt packages beyond the base system. If you want a hobbyist board rather than an appliance, the PC Engines apu2 page has the details, and apu2 boards on Amazon are the usual source.

A note on N100-class mini PCs

Cheap N95/N100 mini PCs (Beelink's EQ series and similar) are often recommended for this, and they will run the generic x86/64 image. There is no OpenWrt-specific endorsement for any given model, though — OpenWrt does not certify consumer mini-PC models, and some vendors' product pages are thin on NIC specs. Before buying, check which Ethernet controller the unit has; Intel NICs are the safe choice, and confirm the machine boots UEFI so you know which image to grab. If you are also considering a mini PC as a Home Assistant server rather than a router, see our best mini PC for Home Assistant roundup. Hardkernel's ODROID-H4 is a well-known N97/N305 x86 board family, but it is listed as discontinued on Hardkernel's store with the ODROID-H5 as successor, so treat old H4 stock accordingly.

The access point problem, and why it is a feature

The x86 image includes no Wi-Fi drivers for typical mini PC hardware, and OpenWrt notes Intel NICs — the standard wireless silicon in almost every mini PC — are generally unsupported or awkward. This is not fixable by installing packages; expect to buy or designate a separate access point. Once you accept it, the setup is actually cleaner than the all-in-one router it replaces: routing and wireless fail independently, the AP can go where Wi-Fi is wanted while the router sits by the modem, and you can upgrade either without rebuilding the other. A cheap wireless router flashed with OpenWrt and set to AP-only mode is one common answer; another is a dedicated AP with VLAN support so your IoT VLAN survives across the whole network. For remote access back into your network, the router is also the natural place to end a VPN tunnel — see Tailscale on OpenWrt and WireGuard on OpenWrt.

Can the router also run Home Assistant?

Usually not, and it is not worth forcing. OpenWrt is a flash-based appliance OS: the combined images use a read-only squashfs root designed to boot reliably and survive power cuts, built with a minimal musl/uclibc toolchain. That is a poor substrate for Home Assistant Supervised, which will not install on OpenWrt. Home Assistant OS and OpenWrt are alternative OS images for the same class of small x86 hardware — each box runs one. A sensible two-box design is a mini PC running OpenWrt as the router plus a second small machine (a Home Assistant Green, a Raspberry Pi, or another mini PC) running Home Assistant. If your hardware budget allows only one box, decide which job it does and size the other accordingly.

FAQ

Can I run OpenWrt on any x86 mini PC or old laptop?

Yes, if it is 64-bit and can boot from USB or an SSD. OpenWrt publishes a generic x86/64 image that needs no per-model build, so any 64-bit x86 machine falls under the Generic x86/64 target. Old 32-bit machines fall under the x86/generic or x86/legacy subtargets instead.

Should I run Home Assistant and OpenWrt on the same mini PC?

Usually not. OpenWrt is a flash-based appliance OS with a read-only squashfs root, and Home Assistant Supervised will not install on it. Home Assistant OS and OpenWrt are separate OS images for the same hardware class — pick one per box and run two machines if you need both.

How do I install OpenWrt on an x86 machine — which image do I pick?

For UEFI machines use generic-squashfs-combined-efi.img.gz; for legacy BIOS machines use generic-squashfs-combined.img.gz. Write the image directly to the target SSD or USB drive with dd or Etcher — never install it from inside a running OS, it is a whole-disk image.

Is a mini PC a better router than a consumer OpenWrt router?

It is a different trade. A mini PC brings a faster CPU, more RAM and often 2.5GbE, and the generic x86/64 target means zero per-model support work. Consumer routers cost less and include radios. Choose x86 for routing headroom and VLANs; choose a consumer router when one box must do everything.

Does OpenWrt on x86 provide Wi-Fi, or do I need a separate access point?

You need a separate access point. The x86 image ships no Wi-Fi drivers, and typical mini PC Intel NICs are generally unsupported or awkward under OpenWrt. Pair the router with a dedicated AP, and use VLANs to keep IoT devices segmented.

OpenWrt vs OPNsense on x86 hardware — which should I run?

Both run well on the same hardware, so this is a software choice, not a hardware one. OpenWrt is lighter and sits closer to the smart-home side of your network (VLANs, WireGuard, Tailscale are all in-repo). OPNsense is heavier and firewall-centric. Our OpenWrt vs OPNsense comparison goes deeper.
