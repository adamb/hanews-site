OpenWrt 25.12: what's new, and should your smart-home router upgrade?

HA News · 14 Nov 2026

OpenWrt 25.12.0, the first stable release of the 25.12 series, shipped on 5 March 2026 with over 4,700 commits since 24.10 branched. The series carries codename "Dave's Guitar", honoring the late Dave Täht of bufferbloat and SQM fame. The latest point release is 25.12.6 (18 October 2026), and it is a security-heavy one. Short answer: if your router runs OpenWrt as part of your smart-home backbone, upgrade to 25.12.x now — 24.10 stopped receiving security updates after September 2026, and the current point release, 25.12.6, patches remotely exploitable holes in the LuCI web server. Per the v25.12.0 release notes, here is what changed and how to move over without losing your install.

The big change: apk replaces opkg

The package manager is no longer opkg. OpenWrt switched to apk, the Alpine Package Keeper. The OpenWrt opkg fork is unmaintained, so there was no future in it. Apk supports most opkg features and few package names changed, but the command-line arguments differ: opkg install becomes apk add, and opkg update is apk update — the details vary, so keep the official opkg-to-apk cheatsheet open the first time you install something new. Scripts and forum copy-pastes that hardcode opkg will break on 25.12. This is the change most likely to trip up anyone who has run the same router setup for years.

Attended Sysupgrade ships by default

The second change is the one that makes upgrades less painful forever after. Attended Sysupgrade (ASU) is now installed by default. The luci-app-attendedsysupgrade LuCI app rebuilds a custom image containing all the packages you currently have installed, then installs it and preserves your configuration. A command-line client, owut, comes by default on devices with larger flash. ASU integrates installed packages into the SquashFS image itself, which is more efficient than a package overlay. In practice: on 25.12 you stop choosing between "keep settings but lose my packages" and "clean flash but reinstall everything by hand."

Smaller changes worth knowing

  • Shell history persists. Command history now survives reboots and sessions via a RAM-backed filesystem. No flash writes by default — writing history to flash would increase write cycles — and it is configurable in /etc/profile.d/busybox-history-file.sh. Per the 25.12.0 release notes.
  • Wi-Fi and network scripts rewritten from shell to ucode — faster and safer, with direct ubus and UCI integration.
  • An OpenWrt video feed (Qt5 plus UI apps) is integrated by default.

Core components and new hardware support

25.12.0 runs Linux kernel 6.12.71 on all targets, with musl 1.2.5 or glibc 2.41, gcc 14.3.0, dnsmasq 2.91, dropbear 2025.89, busybox 1.37.0, a hostapd master snapshot from August 2025, and cfg80211/mac80211 taken from kernel 6.18.7 — all per the release notes.

Hardware support widened noticeably. The qualcommax target now covers ipq50xx and ipq60xx SoCs; realtek extended with 10G Ethernet switch SoCs; there are new siflower (SF21A6826/SF21H8898) and microchipsw/lan969x targets, plus a sunxi/arm926ejs subtarget for Allwinner F1C100/200s boards. Over 180 new devices were added, bringing total device support past 2,200. Most 24.10 devices are still supported.

What is fixed in 25.12.6 — the upgrade driver

25.12.6 (18 October 2026) fixes five unauthenticated, remotely triggerable vulnerabilities in uhttpd, the LuCI web server: a type confusion in POST /ubus/call/, unlimited memory growth, HTTP request smuggling (CL.0), a leaked client reference blocking /ubus/subscribe/, and a Basic Auth realm bypass. The release notes say updating is strongly recommended. If you ever reach LuCI from outside a fully trusted network, this is not optional maintenance.

The same release fixes Wi-Fi issues that matter for modern hardware: hostapd and wpa_supplicant crashes and memory corruption in Wi-Fi 7 MLO frame handling (AP mode affects only 802.11be devices; client mode wpa_supplicant is generally affected — see w1.fi security advisory 2026-1). It also fixes rpcd privilege escalations (symlink file operations, CVSS 8.4; a session-token temp-dir hijack, CVSS 7.0, relevant only with delegated LuCI users), a cgi-io use-after-free, a luci-app-ser2net root-command bug (CVSS 9.9), umdns out-of-bounds reads, and an APuP beacon NULL-dereference crash for anyone with option apup enabled. Crypto libraries moved to Mbed TLS 3.6.7 (including a fix for a remote ECDHE-PSK buffer overflow), OpenSSL 3.5.9 and wolfSSL 5.9.4; the kernel is now 6.12.112.

Should a smart-home router upgrade?

For a router that carries your smart home — the Wi-Fi or VLANs that your Zigbee coordinator, Matter border router and Home Assistant box depend on — the case is unusually clean. The 24.10 series ends security support after September 2026, and OpenWrt urges upgrading to 25.12 before then. Meanwhile 25.12.6 closes unauthenticated remote vulnerabilities in the very web server you use to administer the box. Per the release notes, an unmaintained router with a remotely exploitable LuCI is the kind of device you do not want sitting on the same network as your door locks and cameras. If you segment IoT devices into their own VLAN — see our guide on OpenWrt and IoT VLANs — you have some defense, but the router itself remains a standing target.

Feature-wise, nothing in 25.12 is urgent for a stable install, but apk plus default Attended Sysupgrade make every future upgrade easier. The one feature to know about for home-automation routing: with wireguard and VPN packages now surviving upgrades via ASU, the "clean flash wipes my relay" problem mostly goes away.

How to upgrade safely

The supported paths, from the 25.12.0 release notes:

  1. LuCI Attended Sysupgrade. The app auto-collects your installed packages, requests a custom image, builds and installs it while keeping settings. On 24.10 this app may need installing first; on 25.12 it is default.
  2. The Firmware Selector online builder. Pick your device at firmware-selector.openwrt.org, add your installed packages to the request, and download a custom image.
  3. owut from the command line on devices with larger flash.

Before flashing, take a backup. If you would rather do a scratch install: back up your config, then run sysupgrade -n /tmp/firmware.bin, or flash via LuCI with "keep settings" unchecked.

Two upgrade-path rules. First, sysupgrade from 23.05 straight to 25.12 is not officially supported: go via 24.10, or flash without keeping settings. Second, 24.10 to 25.12 "should be transparent on most devices", with configuration translated on first boot — but two gotchas are documented. On the Bananapi BPi-R4, interface names changed (eth1 → sfp-lan/lan4, eth2 → sfp-wan), which requires upgrading without saving the config. And the busybox cron log level moved: set system.@system[0].cronloglevel to 7, which is now the default. If you log cron jobs on the router, check that after upgrading.

FAQ

Is OpenWrt 25.12 worth upgrading to for a smart-home router?

Yes, mostly for security reasons. The 24.10 series stops receiving security updates after September 2026, and 25.12.6 fixes five unauthenticated remotely triggerable vulnerabilities in the LuCI web server. A router running your Zigbee, Matter and Thread backbone should not sit on an unmaintained release.

What changed between OpenWrt 24.10 and 25.12?

The package manager switched from opkg to apk, Attended Sysupgrade is installed by default, Wi-Fi and network scripts were rewritten in ucode, shell history now survives reboots, and over 180 new devices are supported.

Is upgrading from 24.10 to 25.12 safe? Will I lose my configuration?

On most devices, 24.10 to 25.12 should be transparent: the config is translated on first boot and Attended Sysupgrade rebuilds an image with your installed packages. Upgrading from 23.05 is not officially supported — go via 24.10 or flash without keeping settings. Some devices, like the Bananapi BPi-R4, have interface renames that need a flash without saving the config.

Why won't opkg commands work on OpenWrt 25.12?

OpenWrt 25.12 replaced the opkg fork with apk (Alpine Package Keeper). The opkg fork is unmaintained. Apk supports most opkg features but uses different command-line arguments; OpenWrt publishes an opkg-to-apk cheatsheet.

Which OpenWrt 24.10 devices are supported in 25.12?

Most of them. OpenWrt states most 24.10 devices are still supported in 25.12, which added over 180 new devices for a total above 2,200. Check the Firmware Selector for your exact model.

What is fixed in OpenWrt 25.12.6?

Five unauthenticated remotely triggerable uhttpd (LuCI web server) vulnerabilities, Wi-Fi 7 MLO frame handling crashes and memory corruption in hostapd/wpa_supplicant, rpcd privilege escalations, a cgi-io use-after-free, an Mbed TLS remote ECDHE-PSK buffer overflow, and a luci-app-ser2net root-command bug, among others.
