LoRaWAN gateway: what it does and how to set one up at home

HA News · 11 Nov 2026

A LoRaWAN gateway is the piece of hardware that lets long-range, battery-powered sensors — a water-tank level probe at the far end of a property, a soil-moisture sensor in a field, a freezer alarm in a shed — report into your home network from places Wi-Fi can't reach. This guide covers what a gateway actually does, which kind to buy or build for a house or a farm, and how to connect it to a LoRaWAN network server, using The Things Network or your own ChirpStack install.

What a LoRaWAN gateway actually does

A gateway is a bridge between two worlds. On one side, sensors and trackers talk to it over LoRa, a low-power long-range radio link. On the other side, the gateway forwards those packets over Wi-Fi, Ethernet or cellular to the network server, which is where devices are actually managed and where data is routed onward to your applications or home automation setup.

Three properties of this design matter for anyone running a real property:

  • Every gateway that hears a message forwards it. If a sensor is in range of two gateways, both receive the transmission, and the network server deduplicates the copies and picks the best gateway for any reply. A second gateway adds redundancy rather than a second network.
  • One gateway serves many devices. Per The Things Network's gateway documentation, a single gateway can serve thousands of devices, because LoRaWAN sensors send small packets infrequently.
  • The gateway is roughly interchangeable. Devices are registered on the network server, not on the gateway. Swap gateways and your sensors keep working as long as the new one covers the same area.

Two kinds of gateway hardware

The TTN documentation splits gateway hardware into two families, and the distinction decides how much you can tinker:

  • Minimal-firmware gateways run only packet-forwarding software and nothing else. They are the low-cost option — you get radio reception and forwarding, and little more.
  • OS-based gateways run a full operating system. The packet forwarder runs as a background program, and you can install your own software alongside it — a local data log, a small integration script, or monitoring tools.

Both approaches use the same internal component: a LoRa concentrator, the multi-channel radio chip that lets one gateway listen on many frequency channels at once. For a household with a handful of sensors, a minimal gateway is usually enough. For a farm or a larger property where you want local logging and integrations without round-tripping through the cloud, an OS-based unit earns its keep.

Indoor vs outdoor for a house or farm

The honest answer is that placement matters more than the badge on the box. LoRa is long-range, but a wall is still a wall.

Indoor gateway: plugs into mains power near your router, no weatherproofing to worry about, no ladder required. Sensible when your sensors are close by — around the house, in the yard, in a barn within a few hundred meters. Expect range to shrink substantially through walls and roofs; LoRa signals weaken going through building structure, so an indoor antenna at one end of the house may not hear a tank sensor at the other end of the property.

Outdoor gateway: an antenna on a roof or pole sees the whole property with nothing in the way. This is the right call for acreage, remote gates, or sensors at the far edge of the land. The trade-offs are weatherproofing, mounting, power (often Power over Ethernet, or a solar-plus-battery arrangement on a distant pole), and in lightning-prone areas, lightning protection — The Things Stack's current documentation includes pages on troubleshooting and lightning protection precisely because people mount these things high. Check TTN's docs for their guidance on gateway registration and outdoor placement before you drill anything.

A middle path: put an indoor gateway first, place your sensors, and check received signal quality at each one. If distant sensors report weak signal but nearby ones are fine, a second gateway — or moving the first one outdoors — solves it. Because the network deduplicates, gateways overlap happily.

The network server: The Things Network vs ChirpStack

The gateway is the dumb radio half; the network server is the brain. You have two main routes, and the split is simple:

  • The Things Network (TTN) hosts the network server for you. You register your gateway in their console, register your sensors, and your device data arrives at an integration endpoint. Free for community use, backed by The Things Industries for commercial deployments. This is the fastest route for a household: no servers to maintain, and a global community already running gateways you can piggyback on. One caution: TTN's original V2 documentation is outdated and no longer maintained — the current platform is The Things Stack (V3), so read its docs for gateway registration, packet forwarder configuration and troubleshooting. If you follow an old tutorial that mentions the V2 stack, expect the steps to be different.
  • ChirpStack is open-source network-server software you run yourself. It is built for private or public networks, with a web interface for managing gateways, devices and tenants, data integrations with major cloud providers and databases, and a gRPC API for extension and self-hosting. Per the ChirpStack documentation, it pairs with any gateway that uses a Semtech concentrator and speaks a packet-forwarder protocol, so your gateway choice and your server choice are independent decisions.

Rule of thumb: if you want the simplest path and don't mind community hosting, use TTN. If you want everything local-first — the data staying on hardware you own, on a network only your sensors join — run ChirpStack on a small server. People who care about local control tend to end up there, and it fits homes that already run their automation stack locally.

Regions and bands: get this right before you buy

LoRaWAN is regional. Sensors and gateways must operate in the band allocated for your country, and the network server must have the matching region plan configured.

The common ones are US915 (North America), EU868 (Europe), AU915 (Australia), AS923 variants (parts of Asia), IN865 (India), KR920 (South Korea) and RU864 (Russia), plus older and niche plans like CN470, CN779 and EU433, and the 2.4 GHz ISM2400 band from newer LoRaWAN revisions. ChirpStack documents all of these as supported regions, along with device Class A, Class B (unicast and multicast) and Class C operation and LoRaWAN versions from 1.0.0 through 1.1.0 with RP002 revisions up to RP002-1.0.4.

The practical check: gateway lists its supported region on the datasheet, sensors list theirs, and the network server gets set to match. A US915 sensor will not talk to an EU868 gateway. Buy for your region, and if you import hardware from abroad, check the band before pairing anything.

Setting one up, step by step

The exact screens differ by hardware and by server, but the sequence is the same for The Things Stack or a self-hosted ChirpStack:

  1. Place the gateway. Indoors for a start; higher and closer to your sensors is better. If it's an outdoor unit, follow the vendor's mounting guidance and TTN's lightning-protection notes.
  2. Connect it. Ethernet or Wi-Fi for buildings, cellular for the far end of a property. Confirm the gateway shows as connected in the network server's console.
  3. Register the gateway. On TTN this means registering it in the console with its ID and a key from the label or app. On ChirpStack, add the gateway in the web interface with its ID.
  4. Register the sensors. Each device gets a device EUI and an application key or session keys, from the vendor's datasheet or printed on the device.
  5. Check uplink and downlink. Watch packets arrive in the console. A downlink (server-to-device message) succeeding confirms the gateway's radio path works both ways — some gateways only do downlinks well with good signal, so test from your most distant sensor.
  6. Wire the data into your home. TTN and ChirpStack both offer integrations: webhooks, MQTT, and cloud/database connectors. From MQTT or a webhook into Home Assistant or your broker, sensor values join the rest of your local stack.

Legal note: running your own gateway is legal in most countries because LoRaWAN uses unlicensed bands. There can be country-specific restrictions, in particular around antenna placement, so check your local rules if you plan a tall pole on the roof.

Gotchas worth knowing

  • Old TTN tutorials. Much of the internet's LoRaWAN advice predates The Things Stack V3. The V2 docs are deprecated; anything that walks you through the old console won't match what you see.
  • Region mismatch. The most common "nothing works" cause. Sensor band, gateway band and server region plan must all agree.
  • Downlink range. Uplink from a sensor can work fine while scheduled downlinks struggle, especially at the edges of coverage. Battery-powered sensors on Class A only receive when they transmit, so they're forgiving — but keep it in mind.
  • Power at the far end. An outdoor gateway needs power wherever it is. Plan the cable run, PoE, or solar before deciding the antenna spot.

FAQ

What does a LoRaWAN gateway actually do?

It is a bridge. Devices connect to it over low-power LoRa radio, and the gateway forwards those packets over Wi-Fi, Ethernet or cellular to the network server. The network server deduplicates messages received by several gateways and routes downlinks back through the best one.

Do I need a license to run a LoRaWAN gateway?

Running your own gateway is legal in most countries because LoRaWAN uses unlicensed radio bands. There can be country-specific restrictions, such as rules about antenna placement.

Should I pick an indoor or outdoor gateway for my house or farm?

Indoor gateways are simpler to power and house and fine when your sensors are within radio range of the building. Outdoor gateways cost more to mount and protect but can see further, because an antenna outside on a roof or pole avoids walls that block LoRa signals.

Should I use The Things Network or self-host a ChirpStack network server?

The Things Network hosts the network server for you, which is the fastest route for a household. ChirpStack is open-source software you run yourself for a private network, with a web interface, integrations and a gRPC API. It pairs with any gateway that uses a Semtech concentrator and speaks a packet-forwarder protocol.

How many devices can one LoRaWAN gateway handle?

Per The Things Network gateway documentation, one gateway can serve thousands of devices, because LoRa sensors send small packets infrequently.

Which bands and regions do LoRaWAN gateways and network servers support?

LoRaWAN has regional bands such as US915, EU868, AU915, AS923, IN865, KR920 and RU864, plus 2.4 GHz ISM2400 in newer revisions. Gateway and network server must match your region; ChirpStack lists all of these as supported regions.
